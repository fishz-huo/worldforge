# WorldForge 安装与启动

| 项 | 内容 |
| --- | --- |
| 适用版本 | v0.2.1 |
| 适用范围 | 桌面版（Windows / Tauri）、浏览器、手机与平板（PWA） |
| 相关文档 | [`README.md`](../README.md)（下载与项目概况）、[`docs/使用说明.md`](使用说明.md)（界面与功能）、[`docs/数据模型.md`](数据模型.md) |

本项目的代码可以跑在三种地方，**用的是同一份前端代码**，界面完全一样：

| 想怎么用 | 走哪一节 | 需要准备什么 |
| --- | --- | --- |
| 装成 Windows 桌面应用（推荐，双击就能开） | [§1 桌面版](#1-桌面版装成-windows-应用推荐) | 装一次 Node.js + Rust，之后不用再管 |
| 只在电脑浏览器里看 / 改代码 | [§2 浏览器](#2-电脑浏览器最省事) | Node.js |
| 手机上用（看设定、轻量编辑） | [§3 手机与平板](#3-手机与平板) | 电脑与手机连同一个 Wi-Fi |

> 三条路的**数据各存各的**：桌面版存在应用自己的数据目录，浏览器版存在浏览器的 IndexedDB 里，
> 手机存在手机的浏览器里。它们不会自动同步 —— 搬运方法见 [§4](#4-把数据从一台设备搬到另一台)。
>
> 本软件**不联网、不上传、不需要账号**：没有服务器，也没有云同步。

## 1 桌面版（装成 Windows 应用，推荐）

### 1.1 第一步：装两个工具链（只做一次）

| 工具 | 干什么用 | 装法 |
| --- | --- | --- |
| Node.js 20 或更高 | 跑前端构建 | 到 [nodejs.org](https://nodejs.org/) 下 LTS 版，一路下一步 |
| Rust（含 MSVC 工具链） | 编译桌面外壳 | 到 [rustup.rs](https://rustup.rs/) 装；安装时若提示缺少 "Visual Studio C++ Build Tools"，按提示装上 |

装完开一个**新的**命令提示符（旧窗口读不到新的环境变量），两个都验证一下：

```cmd
node -v
cargo -V
```

两条都能打印出版本号，就可以往下走。

### 1.2 第二步：进入项目目录

下面的 `<项目目录>` 换成你克隆 / 解压出来的那个文件夹（**不是**本文档所在的位置）：

```cmd
cd /d <项目目录>
```

例如项目放在 `D:\code\worldforge`，就写 `cd /d D:\code\worldforge`。
在文件资源管理器里打开那个文件夹，点一下地址栏就能复制出完整路径。

> 怎么确认进对了？敲 `dir`，能看到 `package.json` 与 `src-tauri` 就对了。

### 1.3 第三步：装依赖并启动

```cmd
npm install
npm run tauri:dev
```

- `npm install` 只在第一次（或依赖有更新时）需要，装到 `node_modules\`。
- `npm run tauri:dev` 第一次会编译 Rust 部分，**要等几分钟**；之后启动就很快了。
- 编译完会自动弹出一个 1360×880 的应用窗口。改前端代码保存即热更新，不用重启。

### 1.4 第四步（可选）：打成安装包，以后双击就能开

```cmd
npm run tauri:build
```

产物在 `src-tauri\target\release\bundle\` 下：

- `nsis\WorldForge_x.y.z_x64-setup.exe` —— 单文件安装包，双击即装
- `msi\WorldForge_x.y.z_x64_en-US.msi` —— 企业部署 / 静默安装用

装完之后，开始菜单里就有 WorldForge，**不再需要命令行**，也不再需要 Node.js 与 Rust。
不想要了就用在「设置 → 应用」里卸载。

## 2 电脑浏览器（最省事）

```cmd
cd /d <项目目录>
npm install
npm run dev
```

终端会打印两行地址，浏览器打开其中一行即可：

```
➜  Local:   http://localhost:5173/
➜  Network: http://192.168.1.23:5173/     ← 这一行给手机用，见 §3
```

`Ctrl + C` 停止。想每次改完代码都自动刷新页面，就保持这个窗口开着别关。

> **为什么不用 `npm run build` + `npm run preview`？**
> 开发服务器（`dev`）带热更新，改代码立刻生效，适合边看边改；
> `preview` 只是预览构建产物（`dist\`），想看"最终打包出来长什么样"或要部署到静态站时才用它。

### 端口被占用

本项目的开发服务器**固定**用 5173（Tauri 的 `devUrl` 写死了这个端口），
被占用时会直接报 `Port 5173 is already in use`，而**不会**偷偷换到 5174 ——
因为那样桌面窗口会去加载一个空地址，白屏更难排查。

常见原因是上一次的窗口没关干净。先关掉那个窗口；还不行就找出占用它的进程：

```cmd
netstat -ano | findstr :5173
taskkill /PID <上面查到的 PID> /F
```

## 3 手机与平板

有两条路。**A 只要两分钟**，适合"先在手机上看看"；B 适合"以后天天用"。

### 3.1 A. 同一个 Wi-Fi 直接开（推荐先试这条）

1. **电脑上启动开发服务器**（[§2](#2-电脑浏览器最省事) 的 `npm run dev`）**并让窗口开着**。
   开发服务器已经监听所有网卡（配置文件里就是 `host: true`），不需要额外加参数。
2. **查到电脑的局域网 IP**。新开一个命令提示符：

   ```cmd
   ipconfig
   ```

   在**正在用的那块网卡**（一般是「无线局域网适配器 WLAN」或「以太网适配器 以太网」）下面找
   **`IPv4 地址`**，形如 `192.168.1.23` 或 `10.0.0.15`。
   注意别抄到「默认网关」（那是路由器，通常以 `.1` 结尾）。
   更省事的办法是直接看 `npm run dev` 打印的 `Network:` 那一行。
3. **手机连同一个 Wi-Fi**（必须是同一个；手机开热点给电脑也行，但别一边用流量一边连 Wi-Fi）。
4. **手机浏览器打开 `http://<那个IP>:5173/`**，例如 `http://192.168.1.23:5173/`。
5. **加到主屏幕**：浏览器菜单里选「添加到主屏幕」（Safari：分享 → 添加到主屏幕）。

   > 这条路上是 `http://` 而非 HTTPS，浏览器**不会**注册 Service Worker，
   > 所以**没有离线能力**，也不会出现「安装应用」那一项 —— 只会「添加到主屏幕」。
   > 想要真正的离线可用与「安装应用」，走 B。

**打不开的排查顺序**

| 现象 | 多半是什么 | 怎么办 |
| --- | --- | --- |
| 手机一直转圈、最后超时 | Windows 防火墙拦了 Node | 第一次运行 `npm run dev` 时若弹出防火墙询问，勾**专用网络**并允许；当时点了「取消」就去「Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙」里把 Node.js 勾上 |
| 能开 `http://localhost:5173` 但手机不行 | 抄错了 IP（抄成了默认网关），或两台设备不在同一个网段 | 重新看 `ipconfig`：手机与电脑的 IP 前三段应当相同（如都是 `192.168.1.x`） |
| 上面两条都没问题还是不行 | 路由器开了「AP 隔离 / 客户端隔离」 | 关掉它，或改走 B；也可以用 Tailscale 这类组网工具把两台设备放进同一个虚拟局域网，再用它的 IP 访问 |
| 命令提示符窗口一关手机就断 | 开发服务器是**前台进程**，窗口关了就停了 | 这是正常的：这条路上电脑要一直开着、窗口要一直留着 |

### 3.2 B. 部署到 HTTPS 静态站（真离线 + 「安装应用」）

1. 电脑上构建：

   ```cmd
   npm run build
   ```

   产物在 `dist\`（纯静态文件，没有任何后端）。
2. 把 `dist\` 整个目录传到任意 HTTPS 静态托管：Cloudflare Pages、GitHub Pages、Netlify、自建 Nginx 都行。
3. 手机打开那个网址 → 浏览器会出现真正的「安装应用 / 添加到主屏幕」→ 装上之后**可以离线使用**。

   > 软件本体在公网，但**你的数据不会被上传**：它只写进手机浏览器自己的 IndexedDB。
   > 换句话说，托管方只提供"程序"，看不见你的世界观。

### 3.3 手机上的能力边界

- **能用**：浏览卡片与设定、看地图、拖时间轴看某年发生了什么、写正文、轻量编辑。
- **用不了 / 不好用**：导出时"选目录、直接写盘"在手机浏览器里不可用（点导出会把文件下载到「文件」里）；
  时间轴的长距离拖动这类需要精确指针的操作在触屏上仍然别扭。重活建议留给桌面端。
- **更详细的差异**：见 [`README.md`](../README.md) 的「手机上怎么用」与
  [`docs/使用说明.md`](使用说明.md) 的 §14（已知边界）。

## 4 把数据从一台设备搬到另一台

各端数据独立，「多端运行」指的是同一份程序能跑在多个平台，**不是自动同步**。

1. 在**源设备**上：`设置 → 数据 → 导出完整备份（含图片）` → 得到一个 `.json` 文件。
2. 把文件传过去（微信文件传输助手 / 网盘 / 数据线 / U 盘都行）。
3. 在**目标设备**上：`设置 → 数据 → 导入` → 选中那个文件。

> 手机上请养成导出备份的习惯：浏览器的站点数据可能被系统"回收"，而回收是**没有提示**的。
> 详细说明见 [`docs/使用说明.md`](使用说明.md) 的「数据、保存与备份」一章。

## 5 常见问题

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| `npm install` 报权限 / 脚本被拦 | 用了 pnpm / yarn，或 npm 未批准 esbuild 的构建脚本 | 只用 **npm**（仓库只带 `package-lock.json`）；`package.json` 里已显式批准 esbuild，不需要再批准 |
| `npm run tauri:dev` 报 `beforeDevCommand terminated with a non-zero status code` | 多半是 5173 被占用，或 Vite 崩溃 | 按 [§2 端口被占用](#端口被占用) 处理；再看终端里 Vite 自己的报错 |
| 改了代码界面没变化 | 运行的是旧窗口或旧产物；PWA 还会缓存旧版本 | 关掉窗口重新 `npm run tauri:dev`；浏览器里按 `Ctrl+Shift+R` 强制刷新 |
| 第一次编译等很久 | Rust 要编译几百个 crate | 正常，只此一次；之后增量编译是秒级 |
| 手机上导出没反应 | 手机浏览器不给网页写盘权限 | 见 [§3.3](#33-手机上的能力边界)；要长期用建议走 B 路线并定期导出备份 |
