## 1 项目概述
### 1.1 定位

WorldForge 是一款**本地优先（Local-First）的世界观构建软件**：面向长篇虚构创作的设定管理工具。一句话定位：
> 比 World Anvil 轻量，比 Obsidian 更结构化。
- **轻量**：无后端、无账号、无联网依赖，安装即用；构建产物体积受预算约束（见 §5.2）。
- **结构化**：设定以「卡片 + 关联 + 时间轴 + 地图」的强类型模型组织，而非散落的 Markdown 文件。
- **零切换**：在同一窗口内完成「查设定 → 写正文 → 改设定 → 看时间轴」，不跳转外部工具。
### 1.2 目标用户
| 用户类型 | 典型场景 | 关键诉求 |
| --- | --- | --- |
| 小说 / 网文作者 | 数百万字长篇，人物、势力、时间线庞杂 | 快速反查「这个人是谁的人」「这件事发生在他几岁」；正文与设定同屏 |
| 游戏策划 / 独立开发者 | 世界观设定集、任务线、地图疆域 | 结构化字段（人口、资源、科技水平）+ 可视化时间轴与地图 |
| 跑团（TRPG）主持人 | 自建模组世界、多条平行时间线 | 平行世界分支、版本快照（开团前存档）、参考资料来源管理 |
| 同人 / 二次创作者 | 大量参考资料与考据 | 参考资料卡片 + `[[双链]]` + 标签筛选 |
### 1.3 设计原则
| 编号 | 原则 | 落地要求 |
| --- | --- | --- |
| P1 | 本地优先 | 全部数据落地本机（SQLite 快照 + IndexedDB Blob）；断网可用；提供 JSON 导入导出兜底 |
| P2 | 零切换写作 | 文稿（`docs`）与卡片（`cards`）同窗；`[[卡片标题]]` 双链可直接跳转，不打开新应用 |
| P3 | 结构化但不笨重 | 卡片有类型化字段，但允许空着；正文始终是可写 Markdown 的纯文本区域 |
| P4 | 渐进式可视化 | 可视化是增强而非门槛：可视图（时间轴 / 地图 / 思维导图）与等价文本视图（列表 / 表格 / Markdown）随时互换 |
| P5 | 可维护性 | 单文件不超过 200 行代码，注释详细；禁止引入重量级依赖（见 `docs/架构设计.md` §6.4） |
| P6 | 界面简约可隐藏 | 侧栏 / 面板可折叠，专注模式隐藏一切非必要 UI |
| P7 | 快 | 首屏 < 2s；1000 张卡片下滚动与筛选不卡顿；构建耗时受控 |
### 1.4 v0.1 总体范围

v0.1 交付**可独立使用的单机版本**：14 条功能需求（FR-01 ~ FR-14）全部具备可用形态，插件系统具备完整宿主 API 与 3 个内置示例插件。**不含**云同步、多人协作、移动端原生商店发布、精细地图绘制。

## 2 术语表
| 术语 | 英文 / 标识 | 定义 |
| --- | --- | --- |
| 世界观体系 | world / `worlds` | 顶层容器。一个作品（或一个系列）对应一个体系，`meta` 中保存时间轴配置（刻度单位名、纪元零点） |
| 分支 / 平行世界 | branch / `branches` | 同一世界观下的平行时间线或「如果线」。以 `branch_id` 做数据隔离，可自另一分支 fork |
| 卡片 | card / `cards` | 设定的最小结构化单元。统一一张表，用 `type` 区分角色 / 地点 / 事件 / 底层逻辑 / 势力 / 物品 / 概念 / 参考资料 / 随笔 |
| 差异化字段 | fields | `cards.fields` 中的 JSON，按 `type` 存不同类型特有的键值（如角色的 `birth_t`） |
| 关联 | relation / `relations` | 卡片之间的有向或双向连接，**关系标签由用户自由填写**（师徒、隶属、导致、参考自…），支持双向反查 |
| 标签 | tag / `tags` + `card_tags` | 用户自由填写的扁平分类，多对多；用于跨类型筛选 |
| 泳道 | track / `tracks` | 时间轴的横向行，`kind` ∈ event / character / geo / tech / lore / era |
| 时间轴条目 | timeline entry / `timeline_entries` | 泳道上的一段或一点。`start_t`/`end_t` 为数值刻度（可为负），`instant=1` 表示瞬时点事件 |
| 刻度 | t | 时间轴上的数值坐标。用数值而非日期字符串，以便负值、虚构历法、跨度计算 |
| 纪元 | era / `eras` | 时间轴背景分段（如「第一纪」「大灾变后」），仅用于着色与参照 |
| 地图标记 | pin / `map_pins` | 地图上绑定卡片的位置点 |
| 行政区划 | region / `map_regions` | 地图上的多边形区域，`points` 为归一化坐标数组，`resources` 存人口 / 农业 / 矿产 |
| 文稿 | doc / `docs` | Markdown 长文。`kind` ∈ manuscript 正文 / outline 大纲 / note 笔记 |
| 大纲节点 | outline node / `outline_nodes` | 大纲树节点，`status` ∈ idea / draft / done，可挂接卡片；同一份数据支持文本 / 树形 / 思维导图三视图 |
| 快照 / 版本 | version / `versions` | 整库 JSON 快照（卡片 / 关联 / 标签 / 地图 / 时间轴），用于「保存版本 → 多次修改 → 调出对比」 |
| 资源 | asset / `assets` | 图片。**二进制存 IndexedDB `assets` 仓库，SQLite 只存元数据**，渲染用 `URL.createObjectURL` |
| 插件 | plugin / `plugins` | 单文件 ES 模块，导出 `activate(api)`，通过宿主 API 扩展卡片类型 / 面板 / 命令 / 主题 / 导出器 |
| 落盘 | flush | 把内存 SQLite 导出为二进制快照写入 IndexedDB `kv` 仓库的动作 |
| 脏标记 | dirty | 表示内存数据已被修改、尚未落盘的标志；触发去抖保存 |

## 4 功能需求详述
### FR-01 卡片式管理（P0）
**用户故事**
> 作为作者，我想把角色、地点、事件等设定分别建成卡片，并只填我关心的字段，这样我既能快速录入，又能在需要时查到结构化信息。
**交互流程**
1. 侧栏选择世界观 → 选择分支 → 进入「卡片」视图，默认展示全部类型的卡片列表（标题、副标题、摘要、标签、更新时间）。
2. 点击「新建卡片」→ 选择类型（角色 / 地点 / 事件 / 底层逻辑 / 势力 / 物品 / 概念 / 参考资料 / 随笔）。
3. 表单按 `type` 的表驱动字段渲染（字段字典见 `docs/数据模型.md` §4）：通用区（标题、副标题、摘要、标签）+ 类型区（如角色 `birth_t`/`death_t`）+ 正文 Markdown 区。
4. 保存 → 写入 `cards`，去抖 800ms 后落盘；列表即时反映。
5. 详情页展示：字段、正文、关联（FR-02）、出现的文稿反链、时间轴条目反查（若已上轴）。
**数据落点**：`cards`（主）、`card_tags`、`tags`、`assets`（封面 `cover_asset`）、`settings`（上次选中的筛选条件）。
**验收标准**
- [ ] 9 种 `type` 均可创建、编辑、删除，删除时同步清理 `card_tags` 与相关 `relations`。
- [ ] 角色的 `birth_t`/`death_t` 为数值刻度，支持负数；留空不报错。
- [ ] 列表在 1000 张卡片下滚动流畅，可按类型 / 更新时间 / 标题排序。
- [ ] `pinned=1` 的卡片固定在列表顶部。
- [ ] 关键词搜索可命中 `title`/`subtitle`/`summary`/`body`。
- [ ] 修改后 800ms 内不写盘、之后写盘一次（可用日志验证无写放大）。
**v0.1 范围边界**
- 不做自定义卡片类型的可视化编辑器（由插件 `registerCardType` 提供，见 `docs/插件开发指南.md`）。
- 不做卡片合并 / 批量替换 / 富文本块编辑（正文为 Markdown 源码 + 预览）。
- 不做卡片级权限与历史逐条回滚（使用整库快照 FR-13 兜底）。

### FR-02 卡片自由互相关联（P0）
**用户故事**
> 作为作者，我想说「A 是 B 的师父」「这场战争导致了那个条约」，并希望从任何一端都能看到这条关系。
**交互流程**
1. 卡片详情页「关联」区点击「添加关联」→ 选择目标卡片（带类型筛选的搜索选择器）。
2. 填写关系标签（自由文本，输入时提示历史用过的标签）、备注、是否单向（`directed`）。
3. 保存写入 `relations`；被关联卡片详情页立即出现反向条目。
4. 卡片详情页展示关联分组（按标签分组），支持点击跳转、删除关联。
**数据落点**：`relations`（`from_id`/`to_id`/`label`/`note`/`directed`）。反查索引见 `docs/架构设计.md` §5.5。
**验收标准**
- [ ] 可建立任意同世界观卡片之间的关系，`label` 为用户自由输入，无预设枚举限制。
- [ ] 双向反查：在 `to_id` 卡片页可看到入边，`from_id` 卡片页可看到出边；`directed=1` 时区分方向展示。
- [ ] 删除卡片时其所有关联级联清理，不产生悬空 `from_id`/`to_id`。
- [ ] 同一对卡片允许多条不同 `label` 的关联。
- [ ] 从卡片可一键跳转目标卡片，且不丢失当前视图上下文（返回可回到原卡片）。
**v0.1 范围边界**
- 不做关系图自动布局的交互式编辑（v0.1 仅提供插件示例中的只读关系图谱面板）。
- 不做关系约束校验（如「不能自己关联自己」之外的业务规则）。
- 不做跨世界观关联。

### FR-03 可视化地图编辑器（P1）
**用户故事**
> 作为策划，我想为同一片大陆画多张地图（不同时期、不同分支），在上面标出城市与矿点，圈出各势力疆域并记录人口与资源随时间的变动。
**交互流程**
1. 「地图」视图列出当前分支的地图（`maps`），可新建 / 上传底图（图片进 IndexedDB `assets`）。
2. 进入编辑画布：底图按 `width`/`height` 等比绘制；坐标一律存**归一化值**（0~1）。
3. 添加标记：点击画布落点 → 选择绑定卡片 → 设置 `label`/`icon`/`color`；可拖拽微调。
4. 绘制区划：多边形顶点点击成环 → 填 `name`/`color`/`resources`（人口 / 农业 / 矿产）。
5. 时间维度：为地图设置 `period`/`era`，为区划设置 `period`；使用「时期切换器」查看不同时期的疆域与资源。
6. 只读模式：在地图视图默认只读，可点击标记跳卡片、查看区划资源表。
**数据落点**：`maps`、`map_pins`、`map_regions`、`assets`。
**验收标准**
- [ ] 同一 `world_id` + `branch_id` 下可存在多张地图，`period` 不同的事件/疆域数据互不覆盖。
- [ ] 标记落点保存归一化坐标，窗口缩放后位置仍正确。
- [ ] 标记可绑定卡片；从标记可跳转卡片，从卡片可列出其所在地图与坐标。
- [ ] 区划 `resources` 以表格 + 图形（色块深浅）双呈现，可导出为文本表。
- [ ] 切换时期时，不属于该时期的标记 / 区划可隐藏而非删除。
**v0.1 范围边界**
- **不做精细边界绘制**：无贝塞尔曲线编辑、无吸附、无拓扑校验，多边形为直线段的顶点集合。
- 不做瓦片地图、不做缩放层级（仅整体等比缩放与平移）。
- 不做地图间自动差异比对（由 FR-13 版本快照间接支持）。

### FR-04 可视化时间轴（P1）
**用户故事**
> 作为作者，我想一眼看到「主角 30 岁那年发生了哪场战争，当时他是哪个阵营的」，并看到科技与地理随时间的演进。
**交互流程**
1. 「时间轴」视图按 `tracks` 渲染泳道（事件 / 角色生命线 / 地理变化 / 科技水平 / 底层设定 / 纪元）。
2. 拖动、缩放假轴（数值刻度）；`eras` 作为背景色带与标签。
3. 新建条目：选择泳道 → 填标题 → 拖拽设定 `start_t`/`end_t`，或勾选 `instant=1` 变为点事件。
4. 角色泳道：条目可绑定 `card_id`，系统按该卡 `birth_t` 推算区间年龄；`state` 记录该时间段的身份/状态。
5. 点击条目展开详情：起止、时长、关联卡片、涉及事件列表；可跳到卡片补设定。
6. 文本视图：同数据的表格（泳道 / 标题 / 起 / 止 / 时长 / 关联卡片），可排序与筛选。
**数据落点**：`tracks`、`timeline_entries`、`eras`、`cards`（年龄推算依赖 `fields.birth_t`）。
**验收标准**
- [ ] 六类 `kind` 泳道均可创建、排序（`order_index`）、着色、隐藏。
- [ ] 条目支持瞬时点（`instant=1`）与区间（`end_t > start_t`），并显示时长。
- [ ] 角色泳道在任意刻度 `t` 显示年龄 = `t - birth_t`；跨越 `death_t` 后标记为已故。
- [ ] 纪元 `eras` 背景分段不与条目渲染冲突，刻度可为负。
- [ ] 时间轴数据可一键切换为等价表格文本视图（P4 渐进式可视化）。
- [ ] 地图变化与科技水平可在时间轴上以条目呈现并跳转到对应地图时期 / 卡片。
**v0.1 范围边界**
- 不做甘特式依赖连线与自动排程。
- 不做多分支时间轴的叠加同屏对比（分支切换查看，不并行渲染）。
- 不做真实历法换算（刻度是抽象数值，单位名仅存于 `worlds.meta`）。

### FR-05 底层逻辑写作区（P1）
**用户故事**
> 作为作者，我想在一个安静的地方写「这个世界的魔法为什么会衰减」这类底层设定，边写边引用已有卡片。
**交互流程**
1. 进入「写作」视图：左侧为文稿 / `lore` 卡片目录树，右侧为大编辑区（Markdown 源码 + 实时预览，或仅预览）。
2. 输入 `[[` 触发卡片标题补全 → 插入 `[[卡片标题]]` 双链。
3. 预览中双链渲染为可点击链接，点击跳转到卡片详情页。
4. 「专注模式」隐藏侧栏、目录树与工具栏。
5. 保存 → `docs.content`；若文稿类型为 `manuscript`，可查看本篇的写作统计（由内置插件提供）。
**数据落点**：`docs`、`cards`（`type='lore'`）、`relations`（`label='参考自'`）。
**验收标准**
- [ ] `docs.kind` 三种（`manuscript`/`outline`/`note`）可用，`content` 为 Markdown 原文。
- [ ] `[[标题]]` 可解析为链接并跳转；标题不唯一时给出候选列表；不存在的标题渲染为「待创建」样式且可一键建卡。
- [ ] 卡片详情页能列出「哪些文稿引用了本卡」（反链列表）。
- [ ] 专注模式一键隐藏所有非编辑 UI，退出后恢复原布局。
- [ ] 正文区域始终可直接编辑 Markdown 源码（可视化不是唯一入口）。

**v0.1 范围边界**

- 不做协同光标与评论批注。

### FR-06 图片插入（P1）
**用户故事**
> 作为作者，我想把角色立绘和地图截图直接拖进卡片，不想先上传到任何网站。
**交互流程**
1. 在卡片编辑区或封面区拖拽 / 粘贴图片文件。
2. 前端读取 Blob → 压缩（超过阈值时等比缩放）→ 写入 IndexedDB `assets` 仓库 → 在 SQLite `assets` 表写入元数据（`id`/名称/`mime`/尺寸）。
3. 渲染时 `URL.createObjectURL(blob)` 生成对象 URL，组件卸载时 `revokeObjectURL`。
4. 卡片 `cover_asset` 指向 `assets.id`；正文图片以 Markdown 语法引用该 `id`。
**数据落点**：`assets`（元数据，SQLite）+ IndexedDB 对象仓库 `assets`（Blob）。
**验收标准**
- [ ] 支持 PNG / JPEG / WebP / GIF 拖拽与粘贴插入，写入后刷新应用仍可显示。
- [ ] 图片二进制不进入 SQLite 快照（导出快照体积不随图片增长）。
- [ ] 对象 URL 在组件卸载 / 图片删除时被释放，长时间编辑不出现明显内存增长。
- [ ] 删除卡片时提示是否同时删除其独占图片；未引用图片可在设置中清理。
- [ ] 单张图片超过体积上限时给出明确提示并允许继续（仅缩放，不静默失败）。
**v0.1 范围边界**
- 不做图片裁剪器、滤镜、图层。
- 不做图床 / 外链抓取（可手动填外链 URL，但不代抓）。
- 不做 SVG 编辑与动画 GIF 逐帧处理。

**用户故事**
> 作为作者，我想用树来搭结构，也想用思维导图看全局，还想直接用 Markdown 快速写下来——三者应当同步。

### FR-13 版本快照对比（P1）
**用户故事**
> 作为作者，我想在动大手术前存一个版本，改完后再看看到底改了哪些设定。
**交互流程**
1. 「版本」视图点击「保存版本」→ 填 `name`/`note` → 序列化整库 JSON（卡片 / 关联 / 标签 / 地图 / 时间轴 / 文稿）写入 `versions.snapshot`，并记录 `size`。
2. 版本列表显示名称、备注、体积、创建时间；可命名、可删除。
3. 选择某版本点「与当前对比」→ 生成差异报告：
   - **字段级**：新增 / 删除 / 修改的卡片，逐字段列出旧值与新值；
   - **行级**：文稿正文与卡片正文用 LCS 行级 diff 高亮增删行。
4. 可选择「还原到此版本」（先自动保存当前状态为临时快照，避免误操作不可逆）。
**数据落点**：`versions`（`snapshot` 存 JSON 文本）。
**验收标准**
- [ ] 快照包含卡片、关联、标签、地图（含区划 / 标记）、时间轴、纪元、文稿，不包含图片二进制。
- [ ] 差异报告区分「新增 / 删除 / 修改」三类，并可下钻到字段级。
- [ ] 正文差异以行级 diff 呈现，增删行着色可读。
- [ ] 还原前自动生成当前状态的安全快照。
- [ ] 快照体积与卡片数量呈线性关系；1000 卡片下保存耗时 < 2s（不阻塞 UI，异步序列化）。
- [ ] 快照可用于跨设备迁移（导出 JSON → 另一设备导入）。
**v0.1 范围边界**
- 不做自动定时快照与保留策略（仅手动）。
- 不做三方合并（同时存在 A/B 两版差异并合）。
- 不做增量快照与二进制压缩（v0.2 评估）。

## 5 非功能需求
### 5.1 性能（NFR-P）
| 编号 | 指标 | 目标 | 测量条件 |
| --- | --- | --- | --- |
| NFR-P1 | 首屏可交互 | < 2s | 中端笔记本，冷启动，含 wasm 载入与快照读取（快照 ≤ 5MB） |
| NFR-P2 | 1000 卡片列表滚动 | ≥ 50 FPS | 列表虚拟化或分页，含标签徽标渲染 |
| NFR-P3 | 筛选 / 搜索响应 | < 300ms | 1000 卡片，多标签 AND 筛选 |
| NFR-P4 | 保存去抖 | 800ms | 连续编辑只触发一次落盘 |
| NFR-P5 | 落盘耗时 | < 400ms | 5MB 快照 `export()` + IndexedDB 写入，异步不阻塞输入 |
| NFR-P6 | 时间轴渲染 | ≥ 30 FPS | 6 泳道 / 300 条目拖拽平移 |
| NFR-P7 | 地图渲染 | ≥ 30 FPS | 1 张底图 + 100 标记 + 20 多边形 |
| NFR-P8 | 版本对比 | < 1.5s | 1000 卡片，字段级 + 行级 diff |
### 5.2 体积与依赖（NFR-S）
| 项 | 预算 | 说明 |
| --- | --- | --- |
| 首屏 JS（gzip） | ≤ 250 KB | 含 React、zustand、路由与布局 |
| 非首屏 chunk（gzip，单个） | ≤ 120 KB | 地图 / 时间轴 / 大纲 / 版本各自懒加载 |
| CSS（gzip） | ≤ 40 KB | Tailwind 生产构建（purge 后） |
| sql.js wasm | ≈ 1.2 MB（gzip 后 ≈ 500 KB） | 单独资源，惰性加载并缓存 |
| 桌面安装包（Windows） | ≤ 12 MB | Tauri 2.0，非 Electron |
| 构建耗时 | ≤ 15s | 本地中端机器 `vite build` |
| 依赖白名单 | React / React-DOM / Vite / TypeScript / Tailwind / Radix（shadcn/ui 复制源码）/ zustand / sql.js / lucide-react / clsx+tailwind-merge / date-fns（可选） | 白名单外新增依赖需在 PR 中说明体积增量 |
### 5.3 离线与跨端（NFR-O）
| 编号 | 要求 |
| --- | --- |
| NFR-O1 | 提供 `public/manifest.webmanifest` 与 service worker，满足主流浏览器「可安装」判据 |
| NFR-O2 | 静态资源可离线缓存；应用在完全断网下可启动并完成核心流程 |
| NFR-O3 | Tauri 2.0 打包 Windows（MSI/NSIS）；Android 经 Tauri 移动端打包或 PWA 安装 |
| NFR-O4 | iOS 与 HarmonyOS 在 v0.1 以 PWA 承载（HarmonyOS 走 ArkWeb），文档中不得宣称未验证的原生能力 |
| NFR-O5 | 各端数据互不自动同步，迁移依赖 JSON 导出 / 导入 |
### 5.4 数据安全（NFR-D）
| 编号 | 要求 |
| --- | --- |
| NFR-D1 | 所有业务数据仅存本机；不发起任何遥测或网络请求 |
| NFR-D2 | 支持整库导出 JSON（含 schemaVersion）与导入；导入前校验版本并提示覆盖风险 |
| NFR-D3 | 关键操作（导入、还原、删除分支）需二次确认 |
| NFR-D4 | 落盘在 `visibilitychange`（隐藏）与 `beforeunload` 时强制执行，避免丢数据 |
| NFR-D5 | 提供「导出为 Markdown 合集」作为人类可读的最终兜底 |
| NFR-D6 | 插件无沙箱，安装第三方插件前给出风险提示（见 `docs/插件开发指南.md` §1.3） |
### 5.5 可访问性（NFR-A）
| 编号 | 要求 |
| --- | --- |
| NFR-A1 | 基于 Radix 原语，键盘可完成主流程（Tab / Enter / Esc / 方向键） |
| NFR-A2 | 交互元素有可访问名称；弹层有焦点陷阱与 `Esc` 关闭 |
| NFR-A3 | 正文与背景对比度 ≥ 4.5:1（亮 / 暗主题均满足） |
| NFR-A4 | 支持系统级 `prefers-reduced-motion`，关闭非必要动画 |

## 7 风险与对策
| 编号 | 风险 | 影响 | 概率 | 对策 |
| --- | --- | --- | --- | --- |
| R-01 | sql.js 整库导出导致写放大与卡顿 | 大数据量下编辑发涩 | 中 | 800ms 去抖 + 脏标记；仅在变更时导出；落盘异步化；后续评估增量导出 |
| R-02 | 快照存 IndexedDB 有容量上限（浏览器配额） | 大世界可能写失败 | 中 | 图片与快照分仓；容量探测与提示；导出 JSON 兜底；Tauri 端走文件系统 |
| R-03 | 插件无沙箱，恶意代码可读数据 | 用户数据泄露 | 中 | 安装前显式风险提示；仅从可信来源安装；`toast` 报错隔离；v0.3 评估 Worker 隔离 |
| R-04 | 自研 Markdown 渲染器兼容性不足 | 复杂语法渲染错乱 | 中 | 限定语法子集并文档化；渲染失败降级为纯文本；不以 WYSIWYG 为卖点 |
| R-05 | 依赖体积失控（图表库 / 富文本编辑器） | 违背「小巧」定位 | 中 | 依赖白名单 + CI 体积门槛；可视化自研 SVG/Canvas 轻量实现 |
| R-06 | 移动端 WebView 性能与触控精度 | 地图 / 时间轴难用 | 中高 | 移动端默认文本视图；提供放大手势与命中区域放大；文档标注限制 |
| R-07 | HarmonyOS / iOS 能力未验证 | 过度承诺 | 中 | 明确只承诺 PWA 路径；原生打包列为 v1.0 评估项 |
| R-08 | 数值刻度时间轴对复杂历法表达力不足 | 用户难以录入真实历法 | 中 | `worlds.meta` 存单位名与换算；提供刻度 ↔ 自定义显示表达式；支持负值 |
| R-09 | 版本快照为全量，长期使用体积膨胀 | 存储浪费 | 高 | 允许删除旧版本；v0.2 增量快照；对比时按需加载 |
| R-10 | 单文件 ≤200 行约束与复杂功能冲突 | 文件碎片化 | 中 | 以「机制」而非「界面」为单位拆分；复杂模块允许拆为多个 ≤200 行文件 |
