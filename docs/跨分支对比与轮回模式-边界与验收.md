# 跨分支对比与轮回模式 —— 边界情况与验收清单（附录）
> 主稿见 `docs/跨分支对比与轮回模式-PRD.md`。本文只讲两件事：**会坏在哪里**、**怎么算做完**。

---
## 9 边界情况
### 9.1 分支超过 3 条时，怎么不混乱
规则定死为**硬上限 + 折叠，不做自动抽稀**（自动抽稀会让用户不知道自己在看什么）：
1. **同时对比上限 = 3 个槽位**（窄屏 2 个）。槽位 = 组 = 轨道组，第 4 个加不进来；
2. 「添加对比」下拉里，已在槽位的分支显示为灰勾选并禁用；下拉**底部固定一行**：`最多同时对比 3 条，先移除一条` —— 明确告诉用户为什么点不动，而不是静默失败；
3. 超出的分支**不渲染为空的小行**（那只会占高度、信息还看不清），而是**完全折叠**：在组列表底部显示一条 20px 的汇总条 `另有 4 条分支未对比 [选择加入]`，点了打开槽位选择器；
4. **主世界固定占一个槽位**（可被替换，但不能被移除）——"和谁比"里至少要有一条基准线；
5. 排序规则：主世界永远第一，其余按"周目号/创建时间"从新到旧；**不许按名字排序**（名字里带年份会误导）；
6. 若某个槽位分支被删除：自动回退到最新的可见分支；一个可见分支都没有 → 显示空状态 `这个世界观只有一条分支` + 「新建分支」入口（跳既有流程）。

### 9.2 多个重置锚点怎么处理
| 情况 | 处理 |
| --- | --- |
| **同一泳道设第二个锚点** | 该泳道已有锚点 → 弹确认 `这条泳道已有重置锚点（第1天），要用这一刻替换吗？`；确认则先移旧键再写新键（**同一个 meta 对象里改，不产生两条**） |
| **不同泳道各设锚点** | **允许**（事件线、角色线各有起点是合理的），画布上各画各的菱形 |
| **同泳道锚点刻度倒退**（新锚点比旧锚点更早） | 允许但**提示一次**：`新锚点（第0天）早于已有的（第7天），轮回顺序可能不是你想要的`；只提示、不阻止（这是作者的创作自由） |
| **同泳道两个锚点刻度相同** | 视为重复 → 走"替换"流程，不允许并存 |
| 锚点条目被删除 | 锚点随条目消失（数据就在这条上）；**已经生成的周目不被删除**——确认框里要写明`移除锚点不会删除已生成的第2周目` |
| 锚点条目的刻度被拖动 | 锚点跟着走（它读的是条目自己的 `start_t`），不需要同步任何副本 |
| 只读分支里能不能设锚点 | **不能**（写库即非只读）；按钮置灰并说明 `先解锁这条分支` |
| 单分支视图下要不要显示锚点 | 显示：条目左上角一个 8px 小菱形角标，hover 提示 `轮回重置锚点`；**不**在单分支视图里渲染锚点层（少一层复杂度） |
| 锚点是否参与导出 | 参与（`meta` 随卡片/条目走），但**不**生成额外的文本行；导出文案里不出现"锚点"字样（那是编辑器概念） |

### 9.3 「记忆连线」交织成乱麻：三个开关的优先级
顶栏三个开关，**判定顺序写死在注释里**，不许各组件各判一次：
```
1. [显示连线] 关        → 一条线都不画（数据仍在，右栏「因果关系」区照样列）
2. [只看所选] 开：
     · 有选中条目        → 只画与该条目相关的线（作为起点或终点都算）
     · 没有选中条目      → 不报错、画面不变，底部提示 `先点选一个事件块，再看它的连线`
3. [只看当前周目] 开：
     · 有选中条目        → 与第 2 条同时生效（取交集）
     · 没有选中条目      → 只画"两端都属于当前周目"的线；
                          跨周目的记忆线**隐藏**，但开关旁显示 `已隐藏 3 条跨周目连线`
4. 都不开                → 全画
```
补充规则：
1. **隐藏 ≠ 删除**：被过滤掉的线在 `EntryEditor` 的「因果关系」区仍然完整可见（那里按关系数据列，不看画布开关）；
2. 开关旁必须有**数量反馈**（`已隐藏 N 条`），否则用户会以为线丢了；
3. 「只看当前周目」的"当前"定义：最新周目（见主稿 §5.2）；
4. 跨周目线视觉弱化：线宽 1、透明度 0.7，同周目线保持线宽 1.5 —— 保证主结构不被压过。

### 9.4 旧周目锁定、解锁与"锁定到底锁什么"
| 操作 | 锁定时 | 说明 |
| --- | --- | --- |
| 拖动条目 / 拉两端改起止 | **禁止**（条目上不出现把手、光标 `not-allowed`） | 避免误改刻度 |
| 编辑表单字段 | **禁止**（整块 disabled，顶部一行原因说明） | "看起来能改、点了没反应"最招人烦 |
| 新建 / 删除该组的条目与泳道 | **禁止**（按钮置灰） | 创建也算改 |
| 拉连线 | **允许**（跨周目连线是本功能的核心玩法） | 唯一在锁定时仍放行的写操作，且写入的是 `relations`（新行，不碰旧周目数据） |
| 设置锚点 | 禁止 | 写 `meta` = 改旧数据 |
| 删除整个周目 | **禁止**（要先解锁） | 删分支是重操作，不放进"顺手可点"的范围 |
| 解锁后离开模块再回来 | 回到锁定 | 防止"上次解锁了，这次顺手改坏" |

### 9.5 「从此处重启轮回」是复制操作，三条硬要求
**① 必须是一个事务。** 顺序：`取源分支可见条目与泳道 → 建分支行 → 复制泳道 → 复制条目（刻度平移）→ 写 divergence_t / forked_from`。中途任何一步失败 → 全部回滚；**绝不允许**留下"半个周目"（有分支没条目，或条目数对不上）。这与仓库既有的 `restoreVersion` 教训同源（嵌套事务会报 `cannot start a transaction within a transaction`，那次差点造成空库）。
**② 必须是幂等的（防连点）。** 按钮提交后立即禁用；若用户手快点了两次，第二次必须被识别为"同一次重启"（用本次操作的幂等键，或提交中状态）——**不许生成两个「第2周目」**。
**③ 事务失败要说人话。** 失败时给：`创建第2周目失败，已回滚，你的数据没有被改动` + 一行可复制的技术信息（错误消息），而不是静默失败或白屏。

**刻度平移规则（复制前必须写死，否则新周目会全部叠在原点）**
```
新刻度 = 原刻度 − 锚点刻度
例：锚点在第 1 天（t=245） → 新周目的第 1 天变成 0，第 7 天灭世变成 5
```
边界：瞬时事件（`end_t = null`）只平移 `start_t`；`value`（科技/数值）**不平移**（它是水平值，不是时间）；`note / state / title / card_id / map_id` 原样复制。

**该复制什么、不该复制什么（逐条列清，不要靠"顺手 copy 一行"）**
| 数据 | 复制？ | 理由 |
| --- | --- | --- |
| 泳道（tracks） | ✅ | 新周目要有自己的轨道行 |
| 条目（entries） | ✅（刻度平移） | 轮回的核心就是事件线重演 |
| `card_id`（卡片绑定） | ✅ | 卡片是 world 级数据，跨周目共享（艾拉在哪个周目都是艾拉） |
| `map_id`、`note`、`state`、`title`、`instant` | ✅ | 逐字段原样复制 |
| `meta.cycleAnchor` | ❌ | 新周目不该继承"重置锚点"，否则它自己又是个起点 |
| `relations`（卡片关系） | ❌ | 关系行没有 branch_id 过滤，复制会产生"自己连自己"的自环（见下） |
| 纪元 eras | ❌ | `eras` 是**世界级**的（不随分支隔离），背景色带本来就共用 |

**跨周目连线为什么可行（值得记下的机制）**：`relations` 行只带 `world_id` 与两张卡片 id，`to_id` 指向的卡片可以在另一个分支 —— 所以"第2周目的艾拉（卡片 X）记得第1周目的焚天陨落（卡片 Y）"天然就是一条普通的卡片关系，**不需要任何跨库或特殊机制**。

### 9.7 其它边界
| 情况 | 处理 |
| --- | --- |
| 对比的是一条**普通分支**（不是周目） | 照常对比；只是没有"第N周目"编号与灰暗处理，组标题显示分支名 |
| 分支可见性 | 主世界卡片全分支可见（既有规则）；对比时**不额外过滤**，各分支只显示自己的条目 |
| 某槽位分支下没有任何条目 | 该组渲染一条 28px 空行：`这一条分支还没有时间轴条目`，不渲染空泳道堆 |
| 统一游标落在某组完全没内容的时段 | 该组照常画游标线；右栏「时刻快照」那组显示"此刻没有事件" |
| 同一角色在两组的名称不一致（周目里改名了） | **不做模糊匹配**：泳道名不同就是两条不同泳道（名称对齐是作者自己该维护的事），但要给一行提示 `有 2 条泳道名称相近但不同，未自动配对` |
| 对比模式下按 `Ctrl+滚轮`缩放 | 与单分支一致（同一条刻度尺、同一套补偿），不给每组独立缩放 |
| 对比模式 + `[显示连线]` + 3000 条目 | 见 §10.2 性能表：连线先按"两端都在可见行里"过滤再渲染 |
| 周目名重复（用户自己建了个也叫「第2周目」的分支） | 不做唯一性校验，但在组标题上加序号区分 `第2周目（2/3）` |

### 10.4 明确"不动的部分"
1. **导出链路**：`meta.cycleAnchor` 随数据导出，但不生成额外文本行、不出现"锚点/周目"这类编辑器术语行；
2. **卡片模块**：`RelationEditor` 照旧（新关系类型只是两个新的 `label` 取值，不新增字段）；
3. **地图模块**：本次零改动（上一个 PRD 那枚只读探针标签不属于本次范围）；
4. **纪元 `eras`**：仍然世界级共享，不随周目复制；
5. **`branches` 表结构**：不新增列（周目判定只用既有的 `forked_from` / `divergence_t` / `created_at`）。

## 11 实现顺序建议（每步都能单独验收）
1. **`meta` 列落地**（§0 方案 A）：DDL + 列迁移 + `ENTRY_SPEC` + TS 类型 + `数据模型.md` 更正 → 验收 C5、A8 的前置。
2. **对比模式分组渲染**（`useComparisonMode` + `TimelineBranchGroup` + 槽位选择）：验收 A1 / A2 / A3 / A4 / A14 / B2。
3. **锁定与解锁**（`useReadOnly` + 各处承接）：验收 A6 / A13。
4. **重置锚点**（右栏按钮 + 画布菱形 + 单泳道唯一性）：验收 A7 / A8。
5. **重启轮回**（事务复制 + 刻度平移 + 幂等 + 确认框）：验收 A9 / A10 / B3 / B4 / C1 —— **这一步单独做、单独测，别和其它混在一起**。
6. **跨周目连线**（`edgeStyle` 加两条 + 三开关优先级 + 数量反馈）：验收 A11 / A12 / B5。
7. **角色跨周目状态差异**（左栏小字 + 琥珀色）：验收 A5。
> 每一步做完各自跑 `npm test` + `typecheck` + 目测对齐。第 1 步不动界面，所以第 1、2 步之间可以穿插别的改动而不冲突。

## 12 引用与依据（本稿不是凭空设计的）
| 结论 | 依据 |
| --- | --- |
| `timeline_entries.meta` 不存在 | `schema-extra.ts` 建表语句 + `COLUMN_MIGRATIONS` + `ENTRY_SPEC` + `TimelineEntry` 四处均无 |
| 加列是低风险、幂等、无需提版本号 | `migrate-columns.ts` 的 `runColumnMigrations`（先 `PRAGMA` 再 `ALTER`，每次启动都跑）；`SCHEMA_VERSION` 只影响 `sqlite.ts` 的迁移分支 |
| 加 `meta` 有现成范例 | `outline_nodes` 的 DDL 与 `OUTLINE_SPEC` 都带 `meta`（默认 `{}`），且 `DataModel` 文档 §3.14 也这么写 |
| 周目 = 分支 | `branches` 已有 `name` / `divergence` / `divergence_t` / `forked_from`（`src/types/world.ts`） |
| 跨周目连线可行且无需新表 | `relations` 只带 `world_id` + 两张卡片 id，不按 branch 过滤（`tag.ts` / `schema-core.ts`） |
| 复制类操作必须事务化 | 仓库既有版本还原事故（嵌套事务 + 清空未写回 → 险些空库），已进 lesson |
| 锁定是防误改而非权限 | 用户「数据最重要」红线 + 既有「既然能用就不瞎改」偏好 |
| 对齐是历史重灾区 | 时间轴教训：同一坐标系写了两遍 → 刻度/条目/游标各差一点 |
| 不引入依赖、文件 ≤200 行 | 需求文档 P5 / R-10 与 `docs/架构设计.md` §4 |
