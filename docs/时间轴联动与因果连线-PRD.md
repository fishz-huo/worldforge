## 1 三个功能到底是什么
| 功能 | 用户的处境 | 做完之后 |
| --- | --- | --- |
| 基础联动 | 事件多了以后，"这条和我点的这个人有关系吗"要靠眼睛找 | 点泳道名 → 该泳道全亮、别的变灰；拖游标 → 正在发生的事件亮起来，地图那边的时期也同步 |
| 因果连线 | 「焚天陨落」导致「灵息战争」这件事只写在文字里 | 从事件块边缘拉一条线到另一个事件块，选「导致 / 前置 / 阻止 / 并行」，线上就有箭头 |
| 冲突检测 | 角色死了以后还在打仗、同一时刻在两地同时出现，只有作者自己记得住 | 出问题的块右上角一个红三角，右栏列清楚"谁、在哪个刻度、和谁冲突"，可定位可忽略 |

## 4 状态模型
### 4.1 哪些是"数据"、哪些是"看的"
| 状态 | 归属 | 理由 |
| --- | --- | --- |
| 因果连线本身 | **数据库 `relations` 表** | 是用户的设定，必须落盘、必须能导出 |
| `showEdges`（显示连线）、`onlySelected`（只看所选） | `TimelineModule` 局部 state | 视图开关 |
| `hoveredEntryId`、`draggingEdge`（拖到一半的线） | `useEdgeDrag` 局部 state | 每帧在变，绝不进 store |
| `selectedTrackId`、`selectedEntryId` | 已有 store | 复用，不新增 |
| 忽略名单 `ignoredConflicts` | 本地 state（见附录 §9.5 的可选持久化） | 默认不落盘：它是"这一轮我不想看"，不是设定 |
| 时刻探针（供地图模块同步） | store 里一个**非落盘**键 `momentProbe` | 见 §4.3 |

### 4.2 高亮的判定（一个函数，三处共用）
```
高亮规则（editHighlight）：
  - selectedTrackId === null        → 全部「正常」
  - entry.track_id === selectedTrackId → 「高亮」
  - 其余                             → 「变灰」（opacity 0.35，但仍可点、仍显示红三角）
游标高亮（cursorHighlight）：
  - cursor === null                  → 不参与
  - 条目区间（含 pad，与 MomentPanel 同口径）覆盖 cursor → 「高亮」
```
两套高亮叠加时取「更亮的那个」；**鼠标停留（hover）永远比一切更亮**，保证"我指着的这条一定看得清"。

### 4.3 游标同步给地图：用"探针"，不改数据
需求要「拖动游标 → 地图模块的时期标签同步变化」。这里必须小心：**直接把地图切走等于替用户改数据**（`maps.period` 是设定，`selectedMapId` 是用户的选择）。
做法：
1. `cursor` 仍留在 `TimelineModule` 本地（拖动时每帧在变，进 store 会误导落盘判断）；
2. 模块在 `cursor` 变化时把一个**只读探针**写进 store 的非落盘键：`momentProbe = { t, unit }`；
3. 地图模块订阅 `momentProbe`，在顶栏显示一枚只读小标签：`时间轴游标：245 年`，并高亮 `period_t` 最接近该刻度的地图（**只高亮，不切换**），标签旁给一个「切到这张地图」按钮由用户自己点；
4. `momentProbe` 是视图态：不进 `flush()`、不进快照、不改任何 `*_t` 字段。离开时间轴模块时清空。

### 4.4 坐标系纪律（本次最容易翻车的地方）
- 连线层的每一条边都要把「刻度 → x」与「条目 → y」算出来。**x 必须用调用方传进来的 `toX`（画布坐标，不扣名称列）**，y 用「行序 × 行高 + 行内偏移」，行高与 `TimelineLane` 的 `height`（普通 40 / 数值型 56）**共用同一个常量**，不许各写一个字面量。
- 连线层是**滚动内容的一部分**（和刻度尺、泳道同级），所以它天然跟着横向滚动走；它必须被裁在「内容宽度 − 名称列」之内（`overflow: hidden`），否则横向滚动时线会画到名称列上面去。
- 名称列是 `sticky z-20`；连线层给 `z-0`、条目给 `z-10`、拖拽中的橡皮筋给 `z-30` —— 三层顺序写死在注释里。

## 5 交互流程（照做步骤 · 桌面）
### 5.1 点泳道名，高亮该角色所有事件
1. 点左侧名称列里的「艾拉」（现在这一步只会滚到该泳道第一个条目）；
2. 立即发生：名称列该行底色变蓝（已有）+ **该泳道所有事件块变亮、其他泳道变灰**；
3. 想取消：再点一次「艾拉」，或在空白处点一下（清空 `selectedTrackId`，全屏恢复常态）；
4. 变灰的事件块**依然可以点、可以拖**——只是视觉上退后，不是禁用。

### 5.2 拖游标，联动高亮
1. 鼠标按住刻度尺上任意位置左右拖动（现有能力）；
2. 拖动中：游标线跟着走，**区间覆盖当前刻度的条目块亮起**（与右栏「此刻正在发生」用的是同一套判定，两处结果必须一致）；
3. 松手：游标停在那一刻，顶栏显示 `游标 245 年`；
4. 切到地图模块：顶栏出现 `时间轴游标：245 年` 标签，`period_t` 最接近的地图被高亮描边；
5. 点该标签旁的「切到这张地图」→ 才会真正切换地图（**不自动切，避免替用户改选择**）。

### 5.3 点事件块 → 右栏编辑
1. 点任意事件块；
2. 右栏（抽屉）从「时刻快照」切到「时间轴条目」表单（现有行为）；
3. 若该条目**有冲突**：表单顶部先出现一条红色提示条 `⚠ 与 2 个事件时间重叠`，点它可以跳到冲突区块；
4. 按 `Esc` 或点空白：回到「时刻快照」。

### 5.4 拉一条因果连线
1. **先点中**起点事件块（选中后它的边缘出现 4 个小圆点：上下左右各一个，直径 8px，悬停放大到 10px）；
2. 鼠标按住任意一个小圆点 → 拖动，画面上出现一条跟随指针的灰色虚线（橡皮筋）；此时指针经过的其它事件块高亮描边；
3. 在目标事件块上**松手** → 弹出小菜单，四项：`导致` / `前置` / `阻止` / `并行`；
4. 点「导致」→ 立即在关系表里新增一条 `from=起点卡片, to=终点卡片, label='导致'`，线上出现**实线箭头**；
   - 选「阻止」→ **红色虚线**箭头；选「并行」→ **灰色虚线**（无箭头，双向同色）；「前置」→ 蓝色虚线箭头；
5. 松手处如果是空白（没落在块上）：直接取消，不弹菜单；
6. 想删掉连线：点中这条线 → 变粗并出现一个小叉，点叉删除（同时删掉对应的 `relations` 行，删前给一次确认）。

### 5.5 「只显示当前选中事件的连线」开关
1. 顶栏有 `[只看所选]` 开关，默认关闭（此时若连线很多，画面确实会交织）；
2. **先点中一个事件块**，再打开 `[只看所选]` → 只保留与该条目相关的连线（作为起点或终点都算），其余连线隐藏；
3. 若没选中任何条目就打开开关：不报错，画面**不变**，并在底部提示行显示 `先点选一个事件块，再看它的连线`；
4. 顶栏另有总开关 `[显示连线]`：关掉 = 一条线都不画（连线数据仍在，只是不显示；被隐藏的连线在 `EntryEditor` 的「因果关系」区仍然看得到）。

### 5.6 冲突检测怎么用
1. 打开时间轴模块就自动算好（不弹窗、不打断）；
2. 有冲突的事件块**右上角出现红色小三角**（8px，hover 显示一句话：`时间重叠：与「灵息战争」`或`死亡后参与：艾拉（死于 300 年）`）；
3. 右栏展开时，未选中条目 → 列表出现在「时刻快照」**下方**；选中条目 → 该条目自身的冲突显示在表单**上方**；
4. 点「定位」→ 把该冲突发生的位置滚到视口中央并选中该条目（复用现有 `centerOn`）；
5. 点「忽略」→ 该条冲突从列表和画布上一起消失（按冲突签名记入忽略名单）；
6. 忽略名单在右栏底部有 `已忽略 2 条 · 恢复` 一行，点了全部恢复。

## 6 交互流程（移动端 <768px，与仓库既有 `md` 断点一致）
1. 时间轴在窄屏本来就是"名称列 80px + 横向滚动"，连线层照常渲染，不额外适配；
2. **连线拖拽在触屏上保留**，但圆点放大到 14px（`max-md:` 尺寸），因为手指点不准 8px；
3. 顶栏的 `[显示连线]` / `[只看所选]` 收到「泳道与纪元」旁的下拉里（窄屏顶栏放不下，与既有做法一致）；
4. 冲突列表照常显示在抽屉里；「定位」会把条目滚到视口中央（已扣名称列宽度）；
5. 忽略名单的操作在窄屏下改为长按条目 → 弹「忽略这条」，避免一行里塞两个按钮点错。

## 7 可选项（建议做、可推迟）
| 项 | 建议 | 理由 |
| --- | --- | --- |
| 连线的自动走线（避开其它块） | 不做 | 属于图形编辑器的复杂度；先直连 + 轻微弧线即可 |
| 连线端点吸附到块的最近边 | 做（顺带） | 让线从左边进、右边出，视觉上像流程图 |
| `Esc` 取消拖线 / 关闭菜单 | 做（顺带） | 与既有 `Esc` 取消选中一致 |
| 冲突忽略名单持久化 | 推迟 | 见附录 §9.5，需要一次 schema 决策 |
| 第三条冲突规则（地点冲突：同一地同时两个事件） | 不做 | 用户明确说"两条最简规则"，先不加 |
| 连线参与 md / word / pdf 导出 | 另立需求 | 导出链路本次零改动（见附录 §10.4） |

## 8 交给实现方（AI）的硬约束
1. **只允许改动 `src/features/timeline/` 下的文件**；`src/types/timeline.ts`、`src/lib/query.ts`、`src/types/tag.ts` 只读引用（已有的 `overlaps` / `entrySpan` / `ageAt` / `relationsOfCard` / `RELATION_SUGGESTIONS` 直接用，不许复制粘贴一份）。
2. **唯一例外**：为「游标→地图」同步，允许在 store 里新增一个**非落盘**键（`momentProbe`），并在 `MapModule` 顶栏加一枚只读标签。其他 store 改动一律不做。
3. **不新增 npm 依赖**，不跑 `npm install`；包管理器只用 npm。
4. **单文件 ≤200 行**（含注释）。`TimelineCanvas.tsx` 现在 193 行，动手前**先把底部提示行抽成独立小组件**腾出空间，不要挤成 205 行。
5. **坐标系不许写第二遍**：连线层的 x 一律用调用方 `toX`，行高一律用与泳道共享的常量（见 §4.4）。
6. 关系写入只走 `addRelation({ from_id, to_id, label })`，`label` 取四个固定词之一（`导致` / `前置` / `阻止` / `并行`）；**不要**为此新增 `label` 之外的字段或新表。
7. 顶栏两个开关加 `data-wf-edge-toggle="all|selected"`、连线层加 `data-wf-panel="edges"`、红三角加 `data-wf-conflict="overlap|dead"`，便于自动化探针判定（沿用既有 `data-wf-panel` 做法）。
8. 关键词（本次已踩过、必须遵守）：React 的 `onWheel` 是**被动**的，任何需要在滚轮里 `preventDefault` 的改动都要用原生 `addEventListener(..., { passive: false })`（见 `useCtrlWheelZoom.ts` 头注释）。本次连线不涉及滚轮，但重构时不要顺手改坏它。
