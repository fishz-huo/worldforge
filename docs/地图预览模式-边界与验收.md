# 地图预览模式 —— 边界情况与验收清单（附录）
> 主稿见 `docs/地图预览模式-PRD.md`。本文只讲两件事：**会坏在哪里**、**怎么算做完**。

---
## 9 边界情况
### 9.1 几千个标记时怎么保证悬浮不卡
四个手段叠加，全部在 `src/features/map/` 内实现：
1. **视口裁剪（核心）**：`useMapViewport` 每次算出「可见归一化矩形」= 屏幕矩形反解回 0~1 坐标；
   `usePinCulling` 只保留落在该矩形（外扩 2% 容差）内的标记与区域参与渲染。
   几千个标记在任意缩放档位下，实际挂到 DOM 上的通常只有几十到几百个。
2. **不等 React 重渲染**：缩放 / 平移只改视口容器的 `transform: translate(...) scale(k)`，
   标记的 `left/top` 百分比**一次都不重算**（归一化坐标本来就是相对底图的，天然跟着缩放走）。
   这也是「打点坐标用归一化存储，换底图不错位」这条需求在性能上的红利。
3. **悬浮用委托，不给每个标记挂监听**：`pointerover/pointerout` 只挂在标记层容器上，
   靠 `closest('[data-pin-id]')` 找到目标（给标记加 `data-pin-id`）。
   避免 3000 个 `onMouseEnter` 造成的监听器开销。
4. **低缩放档位降级**：`k ≥ 4` 且可见标记数 > 400 时，自动隐藏名称标签、标记尺寸收缩 30%，
   并在侧栏给一行提示「已简化显示 N 个标记（放大可看全）」。规则写死在常量里，不做自适应调参。

**性能预算（实现后必须实测填表，不许填「应该流畅」）**
| 指标 | 目标 | 测法 |
| --- | --- | --- |
| 3000 个标记进入地图模块的首帧 | < 800ms（dev 模式） | `window.__wf` 造数据 + Performance 面板 |
| 滚轮缩放单帧耗时 | < 16ms（60fps 不掉帧） | 连续滚 20 次，看 Performance 长任务 |
| 鼠标连续划过 20 个标记的浮窗切换 | 无卡顿、无闪烁 | 手动 + React DevTools Profiler 提交次数 |
| 进入预览模式本身 | < 100ms（只是切渲染分支） | 打点计时 |

### 9.2 浮窗边缘碰撞
1. 浮窗尺寸固定 `w-80`（320px，与既有 `WikiHoverCard` 一致），高度按内容自适应，实测一般 200~280px；
2. 放置优先级：**右 → 左 → 上 → 下**（先试右；右侧放不下试左；上下也不行就放下方并对齐元素中心）；
3. 水平方向一律夹在画布容器内（`clamp(8px, x, 容器宽 - 320 - 8px)`），垂直方向同理，保证不出画布；
4. 容器本身**高**装不下浮窗（矮窗口）：浮窗改 `max-h-[70%] overflow-auto`，内部滚动，不撑破画布；
5. 容器**宽** < 360px（手机）：不走浮窗，直接走 §6 的底部抽屉——窄屏上「浮窗 + 翻转」本来就是伪需求。
6. 悬浮在**画布最右侧**的标记上：浮窗翻到左侧，且不再压住该标记自身（`-8px` 间隙）。

### 9.3 底图未上传
1. 预览模式沿用现有提示，不改文案：画布底部居中显示「未设置底图 —— 可直接摆放标记点，之后补图不会错位」；
2. 无底图时**网格仍然隐藏**（预览态统一无网格），但画布底色保留（`bg-grid` 换成纯 `bg-muted/30`），
   否则会出现「一片纯白、以为坏了」的错觉；
3. 缩放 / 平移在无底图时同样可用（标记与区域照常按视口变换）；
4. 「适应屏幕」在无底图时同样按标记 / 区域包围盒计算，不做特殊分支；
5. 顶栏**不弹**任何警告弹窗——这是合法状态（可以先摆点后补图），不要打扰用户。

### 9.4 模式与交互的竞态
| 情况 | 处理 |
| --- | --- |
| 预览态悬浮中，鼠标移到右上角点「编辑模式」 | 先关浮窗（同步清空 `hovered`），再切模式；避免浮窗浮在编辑态画面上 |
| 编辑模式拖标记拖到一半，快捷键切预览 | 忽略切换（拖拽期间 `mode` 锁定），或先 `pointerup` 结束拖拽再切——实现取「拖拽中禁用切换按钮」这一种，规则单一 |
| 切到另一张地图 | 视口**重置**为 `k=1, px=py=0`，悬浮清空，右侧检查器回到「地图概览」 |
| 切模块离开地图 | 视口状态随组件卸载丢弃（下次进来回到铺满态），不持久化、不写库 |
| 窗口尺寸变化 | `ResizeObserver` 触发 `clampViewport()`：容器变小后若 `k` 已无意义则回落到 1 |
| 界面缩放档位（0.85~1.3）被调大 | 画布 `clientWidth` 变化由同一个 `ResizeObserver` 兜住，浮窗的 320px 是 CSS 像素，不受档位影响 |
| 底图透明度滑杆正被拖动 | 拖动期间只改画布上的即时样式，**松手才写库**（沿用「拖动只改预览、松手才提交」的既有经验），避免 800ms 去抖被逐帧重置 |
| 预览态按 `Esc` | 关闭浮窗；若浮窗已关，则取消选中（与仓库既有「Esc 取消选中」一致） |
| 悬浮在一个标记上同时它压在区域上 | 优先级 **标记 > 区域**：标记在最上层且卡片信息更具体；两者同时只显示一张浮窗 |
| 相邻两个标记紧挨着（放大前几乎重合） | 浮窗锚定「指针命中且渲染顺序最后」的那一个（即视觉最上层）；不弹两个、不做合并 |
| 区域只有 1~2 个顶点 | 区域层已能渲染退化图形；预览态**不给**它做特殊处理，它照样可悬浮（能读到区域卡片） |
| 卡片被删除（标记绑的 `card_id` 已不存在） | 直接复用 `WikiHoverCard` 的既有兜底文案「这张卡片已被删除」，不新写分支 |
| 标记没有绑定卡片（临时标记） | 浮窗显示标记自身的 `label / note` + 一行「未绑定卡片」+ 底部「去编辑绑定卡片 →」 |
| 触屏设备但宽度 ≥1024px（平板横屏） | 按「输入方式」而非宽度判定：检测到 `pointer: coarse` 时，悬浮改点击 + 浮窗改浮层（位置同桌面浮窗，不占满宽） |

### 9.5 与既有功能的边界
1. **预览态不提供任何写操作**：打点、新建区域、拖拽改坐标、拖顶点改轮廓、资源热度三选一全部隐藏或禁用；
2. **资源热度着色在预览态保留**（这是"读"的视图，不是编辑）：侧栏切指标在预览态同样可用；
3. **多地图 / 跨时期对比**不受影响：每张地图各自记视口，切换时重置为铺满态（§9.4）;
4. **不碰插件系统**：地图没有插件插口（七类插口里没有地图插口），本功能一律改核心代码；
5. **不碰导出链路**：预览模式是屏幕上的视图，不参与 md / pdf / word / txt 导出，导出内容零变化。

## 11 实现顺序建议（每步都能单独验收）
1. **视口层**（`useMapViewport` + `MapViewportLayer`）：先只做缩放平移 + 适应屏幕，标记仍是圆点；
   验收 A5 / A6 / A7 + B2。
2. **模式切换**（`MapModule` 顶栏 + 画布分支 + 侧栏隐藏工具 + 检查器只读）：验收 A1 / A12 / A14。
3. **视觉降级**（`mapIcons` + 区域弱化 + 侧栏进度条 + 不透明度滑杆）：验收 A2 / A3 / A4 / A8。
4. **悬浮浮窗**（`useMapHover` + `MapHoverCard` + 边缘翻转）：验收 A9 / A10 / A11。
5. **视口裁剪与降级**（`usePinCulling` + 低档位简化）：验收 B1 / B3。
6. **移动端抽屉**（`MapPreviewDrawer` + 手势判定）：验收 A13。
> 每一步做完各自跑一遍 `npm test` 与 `typecheck`，不要攒到最后。
