# 地形图标格式规范（WorldForge · 地图地形符号）

**适用范围**：`src/features/map/` 里的地形符号（山脉、森林、湖泊…那 10 个）。
**不涉及**：地图图钉的图标（`PinGlyph.tsx`，那是另一套，用的是 lucide 图标库，键名都不一样，别混）。
本规范描述的是**替换/新增你自己画的图标**时必须遵守的格式；按此做的改动只碰 1~3 个文件。

> 本文基于本地 HEAD `a06b8b8` 的实际代码逐行核对而成。表格里给出的行号在代码改动后会漂移，以实际文件为准。

---

## §1 图标的 SVG 规范

### 1.1 画布（viewBox）

| 项 | 规定值 | 说明 |
|---|---|---|
| viewBox | **固定 `0 0 24 24`** | 写在 `TerrainGlyph.tsx` 第 68 行，**所有 10 个符号共用这一行**，图形本身不写 viewBox |
| 坐标系 | 左上角为原点，x 向右、y **向下** | 经典 SVG 坐标系。你画的图形"上方"就是 0° 方向（见 §5） |
| 建议绘图区 | **1.5 ≤ x,y ≤ 22.5**（四周留 1.5 的边距） | 留白不够时，符号与选中虚线框会贴上、旋转时像被切了角 |
| 尺寸 | 不做限制，但要"填满格子" | 符号在屏幕上的大小由外层的方块决定，你的图形只占中间一半，看上去就只有一半大 |

**如果你习惯用 32×32 或 100×100 的设计稿**：要么把坐标等比缩到 24（推荐，改动最干净），要么改 `TerrainGlyph.tsx` 第 68 行那一处 viewBox —— 但那一行是 10 个符号共用的，一改全部符号的相对大小都会变，所以**强烈建议统一按 24×24 设计**。

### 1.2 描边与填充（两种预设，二选一或混用）

代码里已有两个预设，你的图形直接沿用它们即可（`TerrainGlyph.tsx` 第 14–24 行）：

**A. 细线型（LINE）—— 8 个符号用它：山脉、丘陵、森林、沼泽、沙漠、草原、城池、关隘**

| 属性 | 值 |
|---|---|
| `fill` | `none` |
| `stroke` | `currentColor` |
| `strokeWidth` | **1.75** |
| `strokeLinecap` | `round` |
| `strokeLinejoin` | `round` |

**B. 实心型（SOLID）—— 只有河流、湖泊用它**

| 属性 | 值 |
|---|---|
| `fill` | `currentColor` |
| `stroke` | `none` |

规则：
- **描边型的图形必须写 `fill="none"`**，否则开放路径会被自动填成一块实心（比如山脉折线会变成一个三角形色块）。
- **实心型的路径要闭合（末尾 `Z`）**，不闭合时浏览器会自动用直线接回起点，形状往往不是你要的。
- 允许的元素：`<path>`、`<circle>`（沙漠的点就是 `<circle fill="currentColor">`）。多个图元要用 `<g>` 或 React 片段包起来。
- **不允许**：`<text>`（依赖字体、缩放后难看）、emoji、位图、`<image>`。
- 若要渐变/滤镜（`<defs>` + `linearGradient`/`filter`）：技术上能跑，但**请写着 `id` 就放弃这个念头** —— 地图上同一符号可能出现几十个（十几个湖泊），每份 DOM 都是同一份 `<defs>`，**id 会重复、引用会打架**，而且渐变会破坏"一键换颜色"的约定。规范上：**不用渐变、不用滤镜、不用 id**。

### 1.3 strokeWidth 的语义（重要，别踩）

- `strokeWidth: 1.75` 是**在 24 格坐标系里的长度**，不是屏幕像素。图形整体等比缩放，所以 **1.75 / 24 ≈ 符号边长的 7.3%**，无论符号放多大，线条相对粗细都不变。
- 实测参考：某地图在"适应屏幕"时 size=1 的符号约 23px（= 底图在屏幕上显示宽度的 6%），线条约 1.7px；把地图放大到 205% 时符号 47px，线条变成约 3.4px。**线条跟着符号一起变粗是刻意保留的效果**（地形是"面纹理"，放大时线太细反而看不清）。
- 你设计时的取值区间：**1.5 ~ 2.5**。低于 1.5 时在左栏 16px 的小预览里已经接近看不见；高于 2.5 时，沼泽那种密集短横线会糊成一片。
- 如果你希望"屏幕上线粗细恒定、不随缩放变"：可以在每个图形上加 `vectorEffect="non-scaling-stroke"`。但要清楚代价——符号放到 3× 时线会显得像发丝；而且它不是继承属性，得写在具体的 `path`/`circle` 上（写在包住森林的那个 `<g>` 里不一定生效，要实测）。**默认建议：不用它。**

### 1.4 是否需要 currentColor —— **必须用**

- 外层按钮上写的是 `color: pin.color`（`MapTerrainLayer.tsx` 第 60 行），SVG 里所有 `stroke`/`fill` 用 `currentColor` 才能吃到这个颜色。**这是"改颜色"功能能工作的唯一前提。**
- 如果你在图形里写死颜色（比如 `stroke="#000"`），那么用户点检查器里的色块改色时，**你的图形纹丝不动**，改色只对别的符号有效——这类毛病不报错，只是"点了没反应"。
- 所以：**单色**。10 个符号全部是单色细线（河湖是单色实心）。多色设计会让"一键换色"只能改一部分，且地图缩小时多色会糊。**用 currentColor 单色。**

### 1.5 格式（从设计软件导出后必须做的事）

从 Illustrator / Figma / Inkscape 导出的 SVG 是 HTML 属性名（kebab-case），而这里是 JSX（camelCase），必须手工转换：

| 导出文件里 | 这里要写成 |
|---|---|
| `stroke-width="1.75"` | `strokeWidth={1.75}` |
| `stroke-linecap="round"` | `strokeLinecap="round"` |
| `stroke-linejoin`、`fill-rule`、`clip-rule` | `strokeLinejoin`、`fillRule`、`clipRule` |
| `class="x"` | `className="x"` |
| `<path d="..."></path>` | `<path d="..." />`（必须自闭合） |
| 根 `<svg width height xmlns>` | **全部删掉**（外层由组件接管） |
| `style="..."` 内联样式 | 改成对象或直接用属性 |
| `id="..."` | **删掉** |

另外：颜色值的 `#` 起头写法在 JSX 属性里是字符串（`stroke="currentColor"` 没问题，写实色才需要引号），自己写死色值属于 §1.4 禁止的做法。

## §2 接入位置

### 2.1 放哪个文件

**唯一位置：`src/features/map/TerrainGlyph.tsx`**（现在 72 行，上限 200 行）。

- 格式：**内联 JSX**，写在文件里那个 `GLYPHS` 对象中（第 26–64 行），键是符号名、值是一段 JSX 图形。
- **不是**独立 `.svg` 文件，也**不是** emoji，也**不是**图标库。

### 2.2 为什么是内联 JSX（而不是独立 .svg 文件）

1. **改颜色会失效**：用 `<img src="lake.svg">` 加载的 SVG 是"外部文档"，**无法继承页面的 `currentColor`**，于是用户点色块改色时图标不变色。要能改色，就必须让 SVG 的图形处在页面 DOM 里（内联）。
2. 仓库没有图片资产管线，10 个独立文件会多出 10 次请求/打包条目，而这里每个符号只有一行路径。
3. 现有先例就是这个风格：图钉图标（`PinGlyph.tsx`）走图标库 + 手写 JSX，地形 10 个是纯手写细线 JSX。保持一致。

如果你**坚持**要独立 `.svg` 文件（方案 B）：把文件放到 `src/assets/terrain/` 下，在 `TerrainGlyph.tsx` 里用 Vite 的 `?raw` 把文件当字符串导入，再用 `dangerouslySetInnerHTML` 内联注入。这条路可行（`?raw` 在本仓已有先例，插件清单就是这么读的），但代价是：① 每个文件里的 `fill`/`stroke` 都得手写成 `currentColor`；② 10 个额外 import；③ 多了一层"字符串注入"，出问题时更难查；④ `TerrainGlyph.tsx` 仍然受 200 行限制。**我建议方案 A（内联 JSX，也就是现状）。**

### 2.3 要改哪几行

**只是替换现有 10 个符号的画法**（你的主要场景）：只改 `TerrainGlyph.tsx` 第 26–64 行里对应键的那一行图形。**其他文件一行都不用动**，四个使用处会自动跟着变：

| 用它的地方 | 位置 | 作用 |
|---|---|---|
| 地图上的符号本体 | `MapTerrainLayer.tsx` 第 79 行 | 画在地图上的那个（大小随底图缩放） |
| 左栏「地形」调色板 | `TerrainPalette.tsx` 第 47 行 | 5 列按钮里的小图标（16px） |
| 右侧检查器（编辑） | `TerrainEditor.tsx` 第 38 行（大图）、第 68 行（"换成别的符号"网格，14px） | 选中后的编辑卡 |
| 右侧检查器（预览） | `TerrainReadonly.tsx` 第 23 行 | 预览模式的只读卡 |

**新增一个符号**：见 §7（要动 2 个文件 + 1 个自测脚本的 2 行数字）。

## §4 命名规则

### 4.1 key（键名，会写进数据库）

- 全小写 ASCII、**单个单词**、不带空格/连字符/下划线（现有 10 个都是如此）。
- 不能与已有键重复。
- 🔴 **一旦用起来就不能改名**：键会被存进 `map_pins.meta` 的 `symbol` 字段，**同时**还写进 `icon` 列（`useMapTerrain.ts` 第 26 行），所以数据库里有两处记录它。改名后：老的行读出来"符号不认识"，**不报错**，静静回落成"山脉"（见 4.4）。你会看到地图上自己画的森林全变成山，且没有任何提示。
- 想换图形不要换键：**保留 key，只改 `TerrainGlyph.tsx` 里那一行的画法**，这样老数据原样不变。
- 若真的必须改名，那是一次**数据迁移**（要写"老键 → 新键"的映射去改已有行），不是改个字符串，需要单独安排。

### 4.2 label（中文名，也会写进数据库）

- 中文名，**至少 2 个字**（自测脚本会卡这条）。
- 它会写进 `pin.label`，也就是**数据库里的文字**；改 label 会让已有符号的名字跟着变（图形不受影响）。
- 同时显示在左栏按钮与检查器里，格子宽度只有约 40px，**建议 2~4 个字**；超过 4 个字会换行或挤。
- 名字要一眼能懂（"湖泊"好过"水域面"）。

### 4.3 color（默认色）

- 格式**必须是 `#rrggbb` 全小写 6 位**（自测脚本用 `/^#[0-9a-f]{6}$/` 卡这条）。三位简写（`#abc`）、大写、`rgb()`、颜色名（`blue`）都会让 `npm test` 失败。
- 语义是"这个符号落地时的默认色"（见 §6）。

### 4.4 兜底与顺序（两条容易忽略的后果）

- `terrainDef()`（`mapTerrain.ts` 第 60–62 行）对**认不出的键一律回落成数组的第一个**。现在第一个是 `mountain`（山脉）。所以：**不要把第一个换掉**，除非你希望所有未知/老数据都变成那个符号。
- 新增符号插在数组哪里，就出现在界面第几格。现在 10 个刚好 5×2；加到 11 个会变成 5+5+1（最后一行左边一个，右边留空，正常）。

### 4.5 新增符号需要改的地方（速查）

| 改哪 | 作用 | 漏了会怎样 |
|---|---|---|
| `mapTerrain.ts` 的类型联合（21–31 行） | 让这个键合法 | 编译不过（好事） |
| `mapTerrain.ts` 的 `TERRAIN_SYMBOLS`（40–51 行） | 名字、默认色、界面格子顺序 | 调色板里没有它，落了也不认 |
| `TerrainGlyph.tsx` 的 `GLYPHS`（26–64 行） | 图形 | **编译不过**（`GLYPHS` 要求每个键都有图，这是安全网） |
| `scripts/map-terrain-selftest.mjs` 的 2 个数字 | 自测里的"共 10 个" | `npm test` 红 |

**替换现有 10 个的画法**：只需要动 `TerrainGlyph.tsx`，**自测一个数字都不用改**。

## §5 尺寸与旋转的语义

### 5.1 size（大小）0.5 ~ 3

- **乘的基准 = 底图宽度的 6%**（常量 `TERRAIN_BASE_RATIO = 0.06`，`mapTerrain.ts` 第 65 行）。
  所以：**size=1 → 符号边长 = 底图宽的 6%**；size=0.5 → 3%；size=2 → 12%；size=3 → 18%。
- 注意这是**底图宽度的百分比，不是屏幕像素**：地图放大时符号跟着变大（图钉则是恒定 24px，两者刻意不同）。
- 符号是**正方形**（宽高比 1:1），高 = 宽，你不用管高度。
- 位置：符号**中心**对准你点的那个归一化坐标 (x, y)，所以放大了也是往四周均匀长。
- 范围与粒度：0.5 ~ 3，步进 **0.05**；越界的值会被夹回区间并对齐到 0.05（手改 JSON 写 9 也会变成 3）。
- 检查器上显示的口径是 `1.00×（底图宽的 6.0%）`。

### 5.2 rotation（旋转）0° ~ 359°

- **0° = 正上方**（你画出来的图形原样、不转）。
- **顺时针为正**，与 CSS 的 `rotate()` 同向。所以 90° 是顺时针转四分之一圈（图形的"上方"指向屏幕右侧）。
- 粒度：**整数度**；负数会绕回来（-90 → 270），超过一圈也会收进（370 → 10）。
- 旋转围绕**符号中心**，符号本体和选中虚线框一起转。
- 手柄在哪：缩放方块在**右下角**、旋转圆点在**正上方**（离框顶边 18 屏幕像素），两者命中区都是 24×24 屏幕像素，**只在编辑模式出现**（预览模式只有符号本身）。所以：**画图时把"朝上"当作默认朝向**——有方向感的符号（河流的流向、关隘的通道）建议按"北朝上"画，这样 90° 就等于"朝东"。

## §6 颜色

### 6.1 默认色怎么来的

- 定义在 `mapTerrain.ts` 第 40–51 行每条记录的 `color` 字段（上表已列）。
- 使用时机只有两个：**① 落一个新符号时**（`useMapTerrain.ts` 第 26 行）；**② 在检查器里"换成别的符号"时**（第 47 行，图形/名字/颜色一起换成新符号的默认色）。
- 落好之后可以随时用检查器里的色块自由改色（原生取色器），**改过的颜色是存在数据库每一行里的，不会因为默认色变了而变**。所以：你以后调 `TERRAIN_SYMBOLS` 里的默认色，**只影响新放的符号**，老符号保持原色。
- 分组逻辑：河湖同蓝、森林草绿、沙漠土黄，其余（山脉/丘陵/沼泽/城池/关隘）统一墨色 `#334155`。这个"墨色打底 + 地貌上色"的分配是刻意的。

### 6.2 单色还是多色 —— **单色**

- 必须单色（用 `currentColor`），理由见 §1.4：多色会让"一键换色"只改一部分，且在 14~16px 的小预览里糊成一团。这也是军事地图符号的通行做法。
- 深浅色注意：画布底色是**浅色 `#F5F4F0` / 深色 `#121722`** 两套，而符号颜色是**写死的十六进制、不随主题切换**。现在这套默认色（尤其墨色 `#334155`）在深色画布上偏暗、对比度偏低。如果你在设计新图标时想两边都清楚，可以挑**中间调**（例如比 `#334155` 亮一档的 `#475569`），但要知道这是**改默认色**，会同时影响浅色画布上的观感，而且是全局的统一决定，建议单独一轮改、别混在"换图形"里。

## §7 最小可用示例：新增一个「火山」

假设 key 定为 `volcano`、中文名「火山」、默认色用沙漠那档土黄。**完整改动清单（照抄即可）**：

**① `src/features/map/mapTerrain.ts`，类型联合（第 21–31 行）**
在 `| 'pass'` 这一行后面加一行 `| 'volcano'`（保持每行一个键、末尾的分号在 `'pass'` 那行不变）。

**② 同文件，`TERRAIN_SYMBOLS`（第 40–51 行）**
加一条记录，形状与相邻行完全一致：key 是 `'volcano'`、label 是 `'火山'`、color 是 `'#b45309'`（**必须小写 6 位十六进制**）。
放哪一行决定它在左栏调色板里排第几格 —— 想让它排在最后，就加在 `pass` 那一条之后。

**③ `src/features/map/TerrainGlyph.tsx`，`GLYPHS`（第 26–64 行）**
在 `GLYPHS` 对象里加一条同键的图，值为一段 JSX：用 `{...LINE}` 的细线样式画一座"山顶开口 + 两道斜边 + 顶部冒烟/三点岩浆"的图形，坐标控制在 1.5~22.5 之间、朝上。
格式示例（**只示范格式，具体形状你自己画**）：

```
volcano: (
  <g {...LINE}>
    <path d="…左上斜边 + 山顶 + 右上斜边…" />
    <path d="…山顶的火焰/烟…" />
  </g>
),
```
