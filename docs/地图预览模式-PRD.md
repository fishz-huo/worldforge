## 1 两种模式的一句话定义
| | 编辑模式（现有，保持不变） | 预览模式（本次新增） |
| --- | --- | --- |
| 用途 | 摆点、改坐标、调区域轮廓 | 看世界、读设定、向别人展示 |
| 网格背景 | `bg-grid` 显示 | 隐藏 |
| 标记样子 | 圆形色点 + 图标（现有圆底按钮） | **SVG 图标**（城市 / 山脉 / 战场 / 遗迹），无圆底、带柔和投影 |
| 区域样子 | 可填充 / 轮廓 / 资源热度三选一 | 边框变细且半透明，填充更淡（只做“疆域暗示”） |
| 侧栏数字 | `标记 12 · 区域 5` 纯数字 | 同一位置改为**比例进度条**（见 §4.3） |
| 鼠标行为 | 拖标记改坐标、拖区域顶点改形状 | 滚轮缩放、按住空白平移、悬浮读卡片 |
| 打点 | 有「打点模式」「新建区域」 | 两者**禁用并隐藏**，防止误操作改数据 |
| 右栏检查器 | 选中即改（表单可写） | 选中先读（表单只读，顶部给一个「去编辑」按钮） |

> 铁律：**预览模式绝不写库**。它的任何操作都不得产生 `updatePin` / `moveRegionPoint` / `addPin` 调用。

## 4 状态模型
### 4.1 放在哪里（关键决策）
| 状态 | 位置 | 为什么不进 `zustand` store |
| --- | --- | --- |
| `mode`（edit/preview） | `MapModule` 局部 `useState` | 纯界面状态；进 store 会参与落盘脏标记 |
| `viewport`（`k/px/py`） | `useMapViewport` 内部 `useState` | 每帧都在变；进 store 会让 800ms 去抖落盘被反复触发 |
| `hovered`（目标 + 锚点） | `useMapHover` 内部 `useState` | 同上，且只影响浮窗 |
| `pins` / `regions` / `map.opacity` | 已在 `zustand` | 它们是真数据，必须落盘 |

> 依据：仓库既有经验「拖动只改预览、松手才读 ref」。视口与悬浮都是「看的」状态，不是「数据」，一律不进 SQLite。

### 4.2 视口换算（唯一算法，不许各算各的）
- 归一化 → 屏幕：`screenX = rect.left + (norm * rect.width) * k + px`（Y 同理）。
- 屏幕 → 归一化：上式反解，再 `clampNorm` 到 0~1。
- 缩放锚点：`zoomAt(factor, anchorX, anchorY)` 必须让「锚点下的那个归一化坐标原地不动」——
  先存 `before = screenToNorm(anchor)`，改 `k` 后再令 `px -= (before.x - after.x) * rect.width`。
- 缩放范围：`k ∈ [1, 8]`；`k = 1` 时 `px = py = 0`（即「原图刚好铺满容器」就是最小态，不允许缩得比容器更小）。
- 边界：`clampViewport()` 保证底图永远不留空白边——`px ∈ [-rect.width*(k-1), 0]`，Y 同理。
- **`toNorm` 必须同时被编辑态与预览态复用**：现在它是 `(clientX-rect.left)/rect.width`，预览态要在分子里减去 `px`、分母除以 `k`。收进 `useMapViewport` 一份，避免两套算法漂移。

### 4.3 侧栏「数字变进度条」的确切含义
预览态下，`MapSidebar` 底部原来那行 `标记 12 · 区域 5` 改为：
1. 保留「标记 12 · 区域 5」文字（信息不能丢）；
2. 其下按 `RESOURCE_METRICS` 逐项列出各区域**占比条**：每行 = 指标名 + 细进度条 + 数值，条长 = 该区域该项值 ÷ 当前地图该项最大值；
3. 复用现有的 `RegionResourceBars` 视觉，不新写一套条。
编辑态保持现状，不动。

## 5 交互流程（照做步骤 · 桌面）
### 5.1 切到预览模式
1. 打开左侧导航的「地图」模块；
2. 顶栏右侧找到 `[编辑模式] [预览模式]` 两个按钮（新增），**点「预览模式」**；
3. 立即发生：网格消失 → 标记变成 SVG 图标 → 区域边框变细变淡 → 顶栏出现 `[适应屏幕]` → 侧栏「绘制工具」整块收起、底部换成比例进度条；
4. 想改回去：**点「编辑模式」**——回到与今天完全一致的画面，选中项、地图、缩放档位都不重置。

### 5.2 底图缩放 / 平移
1. 鼠标移到画布上，**滚轮向前**（或触控板上滑）= 以「鼠标指针所在位置」为中心放大；
2. **滚轮向后** = 以指针为中心缩小，缩到「底图刚好铺满画布」就停住，不会缩出灰边；
3. **按住空白处拖动** = 平移（光标变抓手 `cursor-grab`，拖动中为 `cursor-grabbing`）；
4. **按住标记拖动不生效**——预览态拖标记不会改坐标（防误改数据）；想改坐标请点「编辑模式」。
5. 触控板双指捏合：与滚轮同一套逻辑（浏览器把捏合上报为 `ctrlKey + wheel`），不需要另写手势。

### 5.3 适应屏幕
1. **点顶栏 `[适应屏幕]`**；
2. 画面动画（约 150ms）缩放到「所有标记 + 所有区域刚好装下 + 四周 5% 留白」；
3. 若这张地图**一个标记和区域都没有**：退回「`k=1`、`px=py=0`」的铺满态，不报错、不空白；
4. 键盘等价键：`F`（焦点不在输入框时）；命令面板也可加一条同名命令（可选，见 §7）。

### 5.4 悬浮读卡片（预览模式专属）
1. 鼠标**移入**一个标记或区域内部 → 该元素高亮（标记放大约 1.15 倍、区域描边加粗一档）；
2. 停留约 120ms（防手抖误触）→ 元素旁弹出浮窗；
3. 浮窗内容从上到下：封面缩略图（有则显示）→ 类型徽标（地点 / 势力…）→ 标题 → 副标题 → 摘要（最多 4 行）→ 前 4 个结构化字段 → 「关联事件」一行（该卡片关联的时间轴条目 / 事件卡片，最多 3 条）→ 标签 → 底部提示「点击打开完整卡片 →」；
4. 浮窗**不跟随鼠标移动**（跟手会晃眼）：它锚定在元素旁，指针在元素内部移动时浮窗不动；
5. 鼠标**移出**元素（或移出画布）后约 200ms 关闭；鼠标直接移进浮窗内部，浮窗保持不关，可以滚轮读长内容；
6. **点击**该标记或区域 → 右侧检查器切到该元素的详情（预览态只读），浮窗同时关闭；此时才能切到「卡片」模块打开全文。

### 5.5 从预览回到编辑（读改一体）
1. 在预览态点中「焚天城」→ 右栏显示只读详情；
2. **点右栏顶部的 `[去编辑]`** → 自动切回编辑模式，并保持这个标记处于选中态；
3. 于是可以直接改名称 / 坐标 / 绑定卡片，改完再点回「预览模式」看效果。

## 6 交互流程（移动端 <1024px）
1. **点击**打点或区域（没有悬浮，只有点击）→ 从屏幕底部升起抽屉（Bottom Sheet）；
2. 抽屉内容与桌面浮窗完全一致（同一个 `WikiHoverCard`），顶部有拖拽条，**向下拖**或**点背板**关闭；
3. 抽屉升起时画布仍可见其上约 40%：单指拖动画布 = 平移（抽屉不跟着动）；
4. 缩放：**双击画布 = 放大一档**（`k×1.5`，以双击点为锚）；**双指捏合 = 连续缩放**；两种都不与抽屉手势冲突（抽屉只吃落在自己区域内的手势）；
5. 移动端预览态默认收起左右两侧栏（沿用 `useAutoCollapseDrawers` 的既有规则），需要看列表时点左上角面板按钮；
6. 编辑模式在移动端同样可用（本次不删能力），只是按钮排布沿用现有 `max-lg` 抽屉方案。

## 7 可选项（本稿建议做、但可推迟）
| 项 | 建议 | 理由 |
| --- | --- | --- |
| 键盘 `F` 适应屏幕、`Esc` 关浮窗 | 做（顺带） | 零成本，与仓库既有 `Esc` 取消选中习惯一致 |
| 预览态「分享用」全屏按钮 | 推迟 | 属于展示增强，与本次三条需求无直接关系 |
| 命令面板加「切换地图预览模式」命令 | 推迟 | 需要动 `commands` 注册表，超出地图模块边界 |
| HoverCard 记住上次悬浮位置做「预加载」 | 不做 | 卡片数据全在内存，预加载无收益 |
| 打点类型「城市/山脉/战场/遗迹」写进卡片类型系统 | 不做 | 这是**显示层映射**（`mapIcons.ts`），不进数据库、不进插件 API |

## 8 交给实现方（AI）的硬约束
1. **只允许改动 `src/features/map/` 下的文件**；不得修改 `src/features/cards/CardPreview.tsx`、`src/components/**`、`src/types/**`、`src/lib/**`。若确实需要给 `WikiHoverCard` 传新属性，改为「在 `MapHoverCard` 里包一层并只传现有 props」，不许改它的签名。
2. **不新增任何 npm 依赖**，不跑 `npm install`；包管理器只用 npm。
3. **单文件 ≤200 行**（含注释），注释写明「为什么这样设计」而不只是「做了什么」。
4. 预览态必须**零写库**：不得出现 `addPin` / `updatePin` / `moveRegionPoint` / `updateMap` 调用路径。
5. 顶栏必须显示 `data-wf-panel="map-toolbar"`，预览开关按钮加 `data-wf-mode="preview|edit"`，便于自动化探针判定当前模式（沿用时间轴检查器加 `data-wf-panel` 的既有做法）。
6. 关键词：`onWheel` 是**被动**的，若用 React 的 `onWheel` 直接写缩放，`preventDefault` 会被忽略、浏览器会去缩放整页——必须用原生 `addEventListener('wheel', h, { passive: false })`（可参考 `src/features/timeline/useCtrlWheelZoom.ts` 的写法与注释）。
