## 0 前置更正：`timeline_entries.meta` 不存在（必须先决策）
三点实测结论，证据都在代码里：
1. **表里没有这一列**：`schema-extra.ts` 的 `timeline_entries` 只有 `id / world_id / branch_id / track_id / card_id / title / start_t / end_t / instant / note / state / value / map_id / created_at`；`COLUMN_MIGRATIONS`（`migrate-columns.ts`）也没有给它加过列。
2. **连类型和仓储都没有**：`TimelineEntry`（`src/types/timeline.ts`）没有 `meta` 字段；`ENTRY_SPEC`（`src/lib/db/tables.ts`）的写入列清单里也没有 `meta`。**仓储只写清单里列出的字段**——就算往对象上塞 `meta`，落盘时也会被静默丢弃（`数据模型.md` §"坑"里说的正是这个）。
3. **文档与代码不一致**：`docs/数据模型.md` 第 185 行给 `timeline_entries` 列了 `meta`，第 508 行说「`fields`/`meta`/`resources` 新增键无需迁移」。**这条对 `cards.fields`、`worlds.meta`、`map_regions.resources` 成立，但对 `timeline_entries.meta` 不成立**（那一列从来没有过）。同文档还有三处漂移，见附录 §9.6。

### 0.1 三个选项
| 方案 | 做法 | 代价 | 评价 |
| --- | --- | --- | --- |
| **A（推荐）** | 真加一列 `meta TEXT NOT NULL DEFAULT '{}'`：`schema-extra.ts` 建表加一行 + `COLUMN_MIGRATIONS` 加一条 + `ENTRY_SPEC` 加 `meta` + `TimelineEntry` 加字段 | 改 4 个文件；迁移层已存在、幂等、**不会丢数据**（`ALTER TABLE ADD COLUMN` 只加列） | 与 `outline_nodes.meta` 的既有做法完全一致（那张表就是 DDL + SPEC 都有 `meta`） |
| B | 不加列，把锚点存进某个泳道的**普通条目**（约定 `title='轮回重置'` 的菱形条目） | 零 schema 改动 | 语义藏在字符串里：改标题就失效、导出会当成真事件、以后每次读都要写过滤条件 —— 属于"用着用着会咬人"的方案 |
| C | 复用 `note` 字段塞 JSON | 零改动 | 会覆盖用户备注，**直接违背"数据最重要"的红线**，不考虑 |

> 关于"要不要提 `SCHEMA_VERSION`"：**不需要**。列迁移是每次启动都跑的幂等过程（先查 `PRAGMA` 再 `ALTER`），版本号只影响 `sqlite.ts` 的迁移分支。只需在 `schema-extra.ts`（新库）与 `COLUMN_MIGRATIONS`（老库）**两处都写**，注释里已经提醒过这一点。
> 需要新列的话，建议同时把 `src/types/timeline.ts` 的 `TimelineEntry` 补上 `meta: Record<string, unknown>`，并在 `数据模型.md` 把 §3.11 的 `meta` 说明补成真实状态。

## 3 与现有「全部分支」的关系（必须讲清楚，否则功能会打架）
现状（`WorldForge 平行世界模块`）：顶栏有「当前分支 / 全部分支」切换，新建分支不自动切换；「从当前分支派生」复制当前分支可见的卡片。
本次的**对比模式不是第三个并列开关，而是把「全部分支」升级成"按分支分组的横向对比"**：
1. 顶栏保留「当前分支」（单分支编辑，行为完全不变）；
2. 「全部分支」改名为「**对比模式**」，开启后不再是把所有分支的条目混在一张泳道表里，而是**按分支分组**：每组有自己的组标题分隔条、背景色与锁定状态；
3. 默认槽位 = 当前分支 + 最新的一条 IF 分支（最多 3 个槽位，见附录 §9.1）；
4. **对比模式不切换"当前分支"**，编辑权限仍由锁定规则决定（默认只有最新分支/当前分支可编辑）。

## 5 状态模型
### 5.1 状态归属
| 状态 | 归属 | 理由 |
| --- | --- | --- |
| 周目、锚点、记忆连线 | **数据库**（`branches` 行 + `timeline_entries.meta.cycleAnchor` + `relations` 行） | 是设定，必须落盘、必须能导出 |
| `compareOn`（对比模式开关）、槽位分支列表 | `TimelineModule` 局部 state（可考虑记在 sessionStorage 以便重进保留） | 视图状态 |
| 统一游标 `cursor` | 现有本地 state（**一条**，替代"每组一个游标"） | 需求明确"只有一个统一游标" |
| 锁定状态 | 由数据推导（见 §5.3），不单独存 | 避免"锁了但数据说没锁"的不一致 |
| 解锁（临时只读放开） | 本地 state，**离开模块即失效** | 防止"上次解锁了，这次顺手改坏旧周目" |

### 5.2 周目 = 分支（不新增表）
用户需求要"生成新周目轨道"。**不要新建 cycle 表**——既有的 `branches` 正好有四件套：`name`（叫「第2周目」）、`divergence`（"从第 1 周目第 1 天重启"）、`divergence_t`（重启那一刻的刻度）、`forked_from`（从哪来）。判定规则：
```
一个分支是"周目" ⟺ branches.forked_from != null 且 divergence_t != null
周目号 = 按 divergence_t（再按 created_at）排序后的序号
"当前周目" = 最新的一条（时间轴上默认可编辑的那条）
```
这样"第1周目变灰、第2周目明亮"直接用周目号推出透明度（越新越亮），不需要额外字段。

### 5.3 锁定（只读）怎么定
```
readOnly(分支) =
  （对比模式下）该分支不是槽位里"最新的可编辑分支"
  ∨（轮回模式下）该分支是旧周目（不是最新周目）
  ∨ 用户未对旧周目点过"解锁"
```
顶部要有一条规则**写进代码注释**：锁定是"防误改"，不是"权限"。用户点了解锁就该放行，别再二次确认。

## 6 交互流程（照做步骤 · 桌面）
### 6.1 进入对比模式
1. 点顶栏的 `[对比模式]`（现在的「全部分支」位置）；
2. 时间轴重新排布：出现组标题分隔条，第一组是当前分支（灰底），第二组是自动挑出的最新 IF 分支（淡蓝底，标题右侧带 🔒）；
3. 左侧名称列**照旧只有泳道名**（不改结构）；每条泳道名称下面多一行小字显示它属于哪个分支；
4. 顶栏出现「分支槽位」：`[主世界 ▾][IF线：未觉醒 ▾][+ 添加对比]`；
5. 换槽位：点槽位下拉 → 列出该世界观所有分支 → 选一个 → 立即换；
6. 退出对比模式：再点一次 `[对比模式]` → 回到单分支视图（槽位选择被记住，下次进来还是这几个）。

### 6.2 统一游标
1. 在**任意一条**刻度尺位置按下拖动（刻度尺只有一条，在内容顶部）；
2. 拖动时所有组的所有泳道一起画游标线（同一条竖线贯穿到底）；
3. 松手后顶栏显示 `统一游标 245 年`；右栏「时刻快照」按**所有可见分支**分别列出"此刻正在发生"，并标注分支名；
4. 点组标题分隔条**不会**移动游标（分隔条是分组标题，不是可点区域）。

### 6.3 只读与解锁
1. 旧分支/旧周目的组标题右侧有 🔒；
2. 鼠标移到该组的条目上：条目**不变形、不显示拖拽把手**，光标为 `not-allowed`，tooltip 写 `这一条在「第1周目」，默认只读（点标题上的锁可解锁）`；
3. 想改：点组标题上的 🔒 → 图标变成 🔓，该组恢复正常编辑手感；
4. 离开时间轴模块：自动回到锁定（避免下次进来顺手改坏）；
5. 只读时右栏表单**整块灰掉**并可读，顶部一行说明原因，不要"看起来能改、点了没反应"。

### 6.4 设置重置锚点
1. 点中一个条目 → 右栏出现 `[设为轮回重置锚点]`；
2. 点它 → 画布上该条目**下方 6px** 出现一个 14px 菱形 + 一条短竖线，旁边小字 `重置锚点`；
3. 锚点数据写进 `timeline_entries.meta.cycleAnchor = { isAnchor: true, cycle: N }`（**前提是 §0 采纳方案 A**）；
4. 取消：右栏按钮变为 `[取消重置锚点]`，点一下移除（只删这个键，用户其它 meta 键不动）；
5. 同一泳道重复设置：弹一句确认 `这条泳道已经有重置锚点（245 年），要替换成这一刻吗？`，确认后旧锚点移除。

### 6.5 从此处重启轮回（**数据操作，最需要小心**）
1. 在锚点条目上点右栏的 `[从此处重启轮回]`；
2. 弹出确认框，把将要做的事逐条写清楚（**不写"确定吗"，写清做什么**）：
   - 将新建分支「第 N 周目」，来源「第 N-1 周目」
   - 将复制 **32** 个条目、**5** 条泳道
   - 新周目的刻度从 **0** 开始（原周目 245 → 新周目 0）
   - 旧周目将变为只读（可随时解锁）
   - 这一步可以撤销吗：**不能**（建议先做一个版本快照）
3. 点「创建」→ 全部写入在**一个事务**里（见附录 §9.5），完成后自动切到新周目、游标归零；
4. 若第 2 步到第 3 步之间用户改了数据，按钮要重新算计数（不许拿旧计数去创建）；
5. 创建按钮在提交后立即禁用，直到有了结果（防止连点生成两个周目）。

### 6.6 跨周目拉「记忆残留」线
1. 点中新周目的一个事件块 → 边缘出现拖拽圆点；
2. 拖到**另一个周目**的事件块上 → 松手菜单变成四项再加两项：`记忆残留`（紫色点线）/ `因果继承`（蓝色点划线）；
3. 选完写入 `relations`，`label` 就是这两个词之一（**不新增字段、不新增表**）；
4. 想看清：顶栏加开 `[只看当前周目]`（见附录 §9.3），或点 `[只看所选]`；
5. 跨周目的线在视觉上要弱于同周目内的线：线宽 1、透明度 0.7，避免压过主结构。

### 6.7 左栏看"角色在不同周目的状态差异"
1. 对比两个周目时，同一角色的两条泳道会上下相邻（因为它们分组相邻 + 名称相同，会自然对齐）；
2. 每条泳道名称下的小字显示：`第1周目 · 游标时 24 岁 · 已故` / `第2周目 · 游标时 24 岁 · 觉醒`；
3. **状态差异用颜色标**：同一角色在两个周目的状态文案不同时，把状态小字改为琥珀色；相同时保持灰色（不喧哗）；
4. 拖游标时这些小字实时跟着变（复用现有 `年龄推算` 逻辑，不新增算法）。

1. **先做 §0 的决策**：不确认 `meta` 列方案就不许动"锚点"相关代码；一旦确认，`schema-extra.ts` 与 `COLUMN_MIGRATIONS` **两处都要写**（老库靠后者）。

7. **不新增依赖**、不跑 `npm install`；包管理器只用 npm。
8. 坐标系纪律不变：连线层 x 用统一 `toX`，行高与泳道共用常量；分组**只增加行**，不改任何一处 y 换算的算法。
9. 顶栏加 `data-wf-compare="on|off"`、组标题加 `data-wf-branch="<id>"`、锁加 `data-wf-lock="locked|unlocked"`、锚点加 `data-wf-anchor="1"`，便于自动化探针判定。
10. 对齐红线照旧：**刻度尺、所有组的条目、统一游标、连线层**必须在同一刻度上像素级对齐（这是时间轴历史上翻车最多的地方）。
